## 〇、开工复核结论（2026-10-20）

预写 spec 的「开工时必须复核」三条，逐一核实结果如下 —— **两条产生实质偏差，已回写到 spec**。

| # | 复核项 | 核实结果 | 处置 |
|---|---|---|---|
| ① | V3.2 的指标字典是否已就位 | ✅ 已就位：`backend/src/main/resources/metrics/metric-dictionary.yml` v1（12 条指标）+ `MetricDictionaryTest` 双向校验 + `docs/spec/metric-dictionary.md` 人读面 | 本版**只登记不新定义**（决策 D6） |
| ② | `companion/income.vue` 的前端自算是否已按 V3.2 口径收敛 | ❌ **未收敛** —— 仍在用 `reduce()` 拉全量订单自算「累计 / 已结算 / 未结算」 | 本版必做（票 T4） |
| ③ | 费用模型是否仍与 ADR-0009 一致 | ✅ 一致：`fee`（合同服务费）/ `actualFee`（结算金额）+ `order_fee_item` 两型（`ADVANCE` 代垫 / `SERVICE` 服务费），**没有「平台服务费」这个口径** | 按决策 3.6 只做五项，不引入新金额字段 |

### 偏差 D-3.3-1：「本月」措辞改为「统计区间」

预写 spec §31 / §2.1 写的是「本月完成单数 / 本月收入」，而决策 3.5 要求
「统计时间范围沿用 M10 约定：闭区间、默认最近 30 天、上限 366 天」。

两者不可兼得：**「本月」是一个固定日历月，与可传参的统计区间不是一回事。**
按决策 3.5 为准 —— 所有 V3.3 指标走共享区间 `dto.DateRangeQuery`，
指标名与界面文案统一用「区间」，不出现「本月」。否则同一个数字会因
「默认区间 / 手动传参」被解释成两个口径，正是决策 6.2 要禁掉的那类漂移。

### 偏差 D-3.3-2：概览（区间口径）与画像（累计口径）用**不同字段名**表达

概览回答「这一个月做得怎么样」（区间口径），画像回答「我到底什么水平」（累计口径）。
两者都有「完成率」「服务时长」，如果都叫 `completionRate`，接口契约本身就埋了口径分裂。

处置：**字段名自带口径**——
- 概览：`completedOrderCount` / `serviceDurationMinutes` / `completionRate` / `periodIncome`（区间）
- 画像：`totalCompletedOrderCount` / `totalServiceDurationMinutes` / `totalCompletionRate` / `totalServedElderCount` / `punctualityRate`（累计）

指标字典里两条各占一个 key，统计范围字段写明「统计区间内」/「历史累计」。

### 偏差 D-3.3-3：收入页的「累计收入」改为「区间收入」

决策 3.4 要求新工作台与既有收入页**口径一致**、G8 要求前端零自行计算。
旧 `income.vue` 的「累计收入」是拉全量订单在前端 `reduce()` 算出来的 ——
既违反 G8，也无法用「统计区间」表达（区间上限 366 天，装不下「累计」）。

处置：收入页改为消费 `/income` 端点，**KPI 文案从「累计收入」改为「区间收入」**，
并在页面明示当前统计区间。订单**明细列表仍保留**（那是账单，不是统计指标）。

### 偏差 D-3.3-4：陪诊员端的区间口径按 `visit_time` 过滤（不是 `create_time`）

预写 tickets §四 写的是 `DATE_FORMAT(create_time,'%Y-%m-%d')` 分组，
实现改用了 `visit_time`（`CompanionStatisticsMapper` 的区间过滤与按天聚合两处）。

理由：`elder.visit.order_count`（V3.2 家属端）数的是同一批「已完成订单」，
两端必须用**同一个时间字段** —— 否则决策 6.2「同一指标只有一个口径」就破了。
指标字典里 V3.3 的陪诊员指标也已按 `visit_time` 登记（`companion.*` 各条）。

> ⚠️ 容易混的一点：V3.5 运营驾驶舱的 `operations.*` 区间口径用的是 **`create_time`**（下单日）。
> 两者**不是同一个指标**：`companion.*` 是「某个陪诊员在区间内服务了多少单」，
> `operations.*` 是「平台在区间内接了多少单」，范围与口径本就不同 ——
> 不是「同一指标两个口径」，不要把它们合并。

## 二、T1 · 陪诊员统计 Mapper

**新增**：`backend/src/main/java/org/company/nianglin/mapper/CompanionStatisticsMapper.java`

原生 `@Select` 只读聚合。**每条 SQL 必须写 `deleted = 0`**（不走 `@TableLogic` 注入）。
区间一律用 `[start, end]` 闭区间（`startTime` / `endTime`）。

| 方法 | 用途 | 口径 |
|---|---|---|
| `selectOrderStats(companionId, start, end)` | 概览 | 一行返回：`completedCount`（COMPLETED+REVIEWED）、`cancelledCount`（CANCELLED）、`serviceMinutes`（`SUM(TIMESTAMPDIFF(MINUTE, start_time, finish_time))`，仅 COMPLETED+REVIEWED）、`income`（`SUM(COALESCE(actual_fee, fee))`，仅 COMPLETED+REVIEWED）、`orderAmount`（`SUM(fee)`，仅 COMPLETED+REVIEWED） |
| `selectDailyOrderCounts(companionId, start, end)` | ORDER 趋势 | `DATE_FORMAT(create_time,'%Y-%m-%d')` 分组，状态过滤在 Java 侧 |
| `selectDailyIncome(companionId, start, end)` | INCOME 趋势 | 按天 `SUM(COALESCE(actual_fee, fee))`，仅 COMPLETED+REVIEWED |
| `selectDailyRating(companionId, start, end)` | RATING 趋势 | `order_review` JOIN `companion_order`，按 `order_review.create_time` 分组，`AVG(score)`，仅 `is_valid = 1` |
| `selectLifetimeOrderStats(companionId)` | 画像 | 累计：`totalCompletedCount`、`totalCancelledCount`、`totalServiceMinutes`、`totalServedElderCount`（`COUNT(DISTINCT elder_id)`）、`acceptedCount`（`accept_time IS NOT NULL`） |
| `selectOnTimeArrivalCount(companionId)` | 准时率分子 | 存在 `node='ARRIVE'` 打卡且打卡时间 ≤ 订单 `visit_time` 的订单数（每单取最早一次 ARRIVE） |
| `selectDepartmentStats(companionId)` | 擅长服务 | 按 `department` 分组统计 COMPLETED+REVIEWED 单数，取 TOP N |
| `selectSettlementStats(companionId, start, end)` | 收入中心 | 按 `payment_status` 分组：`UNPAID` / `SETTLED` 的 `SUM(COALESCE(actual_fee, fee))` |
| `selectFeeItemTotals(companionId, start, end)` | 费用构成 | `order_fee_item` JOIN `companion_order`，按 `item_type`（`ADVANCE`/`SERVICE`）分组求和 |
| `selectProfileScore(companionId)` | 平均评分 | `companion_profile.score`（**不重算**） |

**约束**：
- 「已完成」= `COMPLETED` + `REVIEWED`（铁律，见 `StatisticsMapper` 类注释）。
- `serviceMinutes` 只统计 `start_time` 与 `finish_time` **均非空**的订单。
- 分数与金额统一用 `BigDecimal`，Service 侧统一 `setScale(2, HALF_UP)`。

### 3.2 指标口径（逐条写死）

| 指标 | 公式 | 范围 |
|---|---|---|
| 区间完成单数 | `COUNT(status IN ('COMPLETED','REVIEWED'))` | 统计区间 |
| 区间服务时长 | `SUM(finish_time − start_time)`（分钟），仅 COMPLETED+REVIEWED | 统计区间 |
| 区间完成率 | `(COMPLETED+REVIEWED) / (COMPLETED+REVIEWED+CANCELLED)`，**拒单不计入分母** | 统计区间 |
| 区间收入 | `SUM(COALESCE(actual_fee, fee))`，仅 COMPLETED+REVIEWED | 统计区间 |
| 订单金额 | `SUM(fee)`，仅 COMPLETED+REVIEWED | 统计区间 |
| 平均评分 | `companion_profile.score`（**不重算**） | 累计 |
| 累计完成单数 | `companion_profile.order_count`（既有冗余口径） | 累计 |
| 累计服务时长 | `SUM(finish_time − start_time)`，仅 COMPLETED+REVIEWED | 累计 |
| 累计服务老人数 | `COUNT(DISTINCT elder_id)`，仅 COMPLETED+REVIEWED | 累计 |
| 累计完成率 | `(COMPLETED+REVIEWED) / (COMPLETED+REVIEWED+CANCELLED)` | 累计 |
| 准时率 | 分子：`ARRIVE` 打卡时间 ≤ `visit_time` 的订单数；分母：已接单订单数（`accept_time IS NOT NULL`）。**无 ARRIVE 打卡 = 不准时** | 累计 |
| 擅长服务 | `department` 维度 TOP N（N ≤ 5），**样本 < 5 单的科室不展示** | 累计 |
| 待结算 / 已结算 | 按 `payment_status` 分组求 `SUM(COALESCE(actual_fee, fee))` | 统计区间 |
| 费用构成 | `order_fee_item` 按 `item_type`（`ADVANCE`/`SERVICE`）分组求和 | 统计区间 |

### 3.3 VO 字段（**字段名自带口径**，见偏差 D-3.3-2）

```java
// CompanionWorkbenchOverviewVO

// CompanionTrendVO

// Series: String name; List<BigDecimal> data;   // name 结构字段 / data 指标

// CompanionServiceProfileVO

Integer totalCompletedOrderCount;               // 指标
Integer totalServedElderCount;                  // 指标
String punctualityRate;                         // 指标

Integer totalServiceDurationMinutes;            // 指标

// CompanionExpertiseVO

// CompanionIncomeVO

String advanceTotal;                            // 指标

```

### 3.4 通用约定

- 区间：`DateRangeQuery#toRange()`（默认最近 30 天、上限 366 天、闭区间、超限 `9002`）。
- 空数据：返回 **0 / 空数组**，**不返回 `null`，不报错**。
- 比率：百分数字符串，两位小数（复用 `ChartDataVO.percent(numerator, denominator)`）。
- 金额：`BigDecimal` → `setScale(2, HALF_UP)` → `toPlainString()`。
- 分桶：DAY / WEEK / MONTH（`StatisticsGranularity`），**无数据的桶补 0**，
  `categories` 与每个 `series.data` 长度**严格一致**。
- 趋势维度：`ORDER` / `INCOME` / `RATING`，非法值 → `BusinessException(ResultCode.PARAM_ERROR)`。

## 六、T5 · Service 层口径单测

**新增**：`backend/src/test/java/org/company/nianglin/service/CompanionStatisticsServiceTest.java`（Mockito 范式）

必须覆盖（每条业务规则**至少一条正向 + 一条反向**）：

1. 完成率：**拒单不计入分母**（反向：把拒单计入分母 → 断言必须变红）
2. 准时率：分子分母；无 ARRIVE 打卡算不准时
3. 擅长标签：**样本 < 5 单的科室不展示**；TOP N ≤ 5
4. 「已完成」= COMPLETED + REVIEWED（REVIEWED 必须计入）
5. 收入用 `COALESCE(actual_fee, fee)`（`actual_fee` 为 null 时回退 `fee`）
6. 待结算 + 已结算 = 实际收入（分母口径一致）
7. 空数据 → 0 / 空数组，不返回 null、不抛异常
8. 趋势分桶：无数据的桶补 0，`categories` 与 `series.data` 长度一致
9. 非法 `dimension` → `BusinessException`
