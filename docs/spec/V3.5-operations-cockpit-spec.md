## 〇、这一版只做两件事

V3.5 回答的问题是：**「管理员能不能快速发现平台异常？」**

迭代计划 §41 把它说得很准：从「管理数据」升级为「**发现平台问题**」。

所以本版**只做两件事**：

1. **一个概览** —— 打开后台首页 30 秒内知道平台是否正常；
2. **一个异常中心** —— 看到异常**并且能直接去处理**。

「处理」的部分是硬要求：决策 5.4 明写「异常卡片到处理页面必须**可达**，不允许『看到了但处理不了』」。

## 一、模块拆分

| 模块 | 内容 | 复用资产 | 新增 |
|---|---|---|---|
| **FR-Overview** | 平台概览 | M10 `StatisticsService.overview` | `GET /api/admin/operations/overview` |
| **FR-Exception** | 异常中心 | **V3.1 的风险中心**（决策 5.1：聚合，不另建判定） | `GET /api/admin/operations/exceptions` |
| **FR-Trend** | 趋势分析 | M10 的 `emptyAxis` / `StatisticsGranularity` | `GET /api/admin/operations/trend` |
| **FR-Health** | 平台健康度 | 上述聚合 | `GET /api/admin/operations/health` |
| **Frontend** | 驾驶舱首页 | 既有后台布局 | 1 页 + 异常卡片 |

## 二、接口契约

> 管理端类级 `@PreAuthorize("hasRole('ADMIN')")`。

| 端点 | 内容 |
|---|---|
| `GET /api/admin/operations/overview` | 今日订单 / 完成 / 服务中 / 待接单 / 履约率 / 平均接单时间 / 投诉率 / 平均评分 |
| `GET /api/admin/operations/exceptions` | 异常中心：① 需人工介入订单（**聚合 V3.1 风险中心**）② 超匹配预警时间订单 ③ 近期投诉率异常陪诊员 ④ 用药漏服异常 |
| `GET /api/admin/operations/trend?dimension=&range=` | 订单 / 陪诊员活跃 / 履约率 / 投诉 / 评价 / 用药任务六条趋势；`range` ∈ `TODAY` / `LAST_7D` / `LAST_30D` / `CUSTOM` |
| `GET /api/admin/operations/health` | 平台健康度 = 6 个客观指标 |

### 2.1 平台健康度：6 个并列指标，**不给合成分**（决策 5.2）

```
履约率 · 接单速度 · 完成率 · 投诉率 · 平均评分 · 活跃陪诊员数
```

**不做**「AI 平台健康指数 96」这类无法解释的数。
若将来要总分，必须先有书面公式并登记进指标字典。

### 2.2 异常中心的四条来源

| 异常 | 来源 | 处理入口 |
|---|---|---|
| 需人工介入订单 | **V3.1 的 `fulfillment_risk = MANUAL_REQUIRED`** | `/admin/order` |
| 超匹配预警时间订单 | V3.1 的 `fulfillment_risk ∈ {WARNING, URGENT}` | `/admin/order` |
| 近期投诉率异常陪诊员 | `complaint` 聚合（阈值配置化） | `/admin/complaint` |
| 用药漏服异常 | `medication_task` 漏服桶聚合 | `/admin/order`（无专门页面时给最近订单） |

⚠️ **决策 5.1：异常中心聚合 V3.1 的风险中心，不另建一套风险判定。**
两套判定必然漂移 —— 这正是 V3.2 在用药三桶上踩过的坑。

### 2.3 每张异常卡片都必须可达

每个异常项返回 `linkUrl` 指向**真实存在**的处理页。
E2E 逐个点开验证 —— 「看到了但处理不了」是本版最典型的假绿。

## 三、测试矩阵

| 层 | 锁住什么 |
|---|---|
| Service 单测 | 每条趋势的口径与分桶；空数据返回 0 或空序列而不是报错 |
| 异常中心 | 与 V3.1 风险中心**同源**（数量一致）；每项都有 `linkUrl` |
| 越权矩阵 | 非管理员一律 403 |
| E2E | 驾驶舱首页渲染；四类异常卡片各自可达；自定义区间生效；空数据走空态 |

**反向验证**：把异常中心的风险判定从「复用 V3.1」改成「另算一套」→ 与风险中心的数量对不上，变红。
