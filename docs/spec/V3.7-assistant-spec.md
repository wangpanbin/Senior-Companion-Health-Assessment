## 一、目标与边界

### 1.1 一句话

家属在 `/family/assistant` 用自然语言提问，得到**可溯源**的回答；问到「找个陪诊员」时，助手把就诊信息回填进下单草稿，订单建成后由 V3.4 的规则引擎给出**可解释**的候选陪诊员，助手负责把「为什么是他」讲成人话。

### 1.2 三条硬边界（ADR-0020 决策 2 / 5 / 6）

| # | 边界 | 违反后果 |
|---|---|---|
| B1 | **助手不改排序**：不得重排候选、不得改分、不得补充 `CompanionMatchVO` 之外的事实 | 违反 ADR-0016「不允许出现没有理由的分数」 |
| B2 | **助手不建订单**：只填草稿，提交由用户在下单流程确认 | PENDING 订单污染陪诊员大厅 |
| B3 | **助手不碰医疗**：诊断 / 用药 / 剂量 / 疗效一律固定拒答 | 违反 `AGENTS.md` §0.1-1 与 §61.3 |

### 2.1 进程与端口

| 进程 | 端口 | 启动 | 对外暴露 |
|---|---|---|---|
| Java 后端 | 8080 | `mvn -Dspring-boot.run.profiles=dev spring-boot:run` | `/api/**` |

`ai-service` **只监听 127.0.0.1**（`--host 127.0.0.1`），不直接暴露给浏览器。浏览器只与 `/api` 说话。

### 2.2 请求链路

```
浏览器
  │ POST /api/assistant/chat  { question, history[], orderId?, elderId? }
  │ Authorization: Bearer <JWT>
  ▼
AssistantController (@PreAuthorize hasRole('FAMILY'))
  ▼
AssistantServiceImpl
  ├─ ① 限流      Redis INCR assistant:rl:{userId}:{minuteBucket}  > limit → 10001
  ├─ ② 上下文装配（本次请求唯一一次查库）
  │    elders       ← ElderService（当前家属绑定的老人，脱敏名）
  │    order        ← OrderService（归属校验；他人 → 3004）
  │    candidates   ← OrderService#recommendCompanions（仅 PENDING 才装）
  │    recentOrders ← OrderService（最近 N 单摘要）
  ├─ ③ 调 Python  POST {service-url}/internal/assistant/chat
  │    └─ 连接失败 / 超时 / 非 2xx / 响应体缺 answer → 走 ④
  ├─ ④ 兜底：本地读 faq.json 直接返回答案原文（degraded=true）
  └─ ⑤ 兜底也失败（faq.json 不可读）→ 10002
  ▼
Result<AssistantChatVO>
```

### 2.3 Python 内部链路

```
POST /internal/assistant/chat
  ├─ guard.scan_input(question)
  │    ├─ 辱骂 / 违规引流 → raise IllegalQuestion → 400 + code 10003
  │    └─ 医疗意图       → 直接返回 REFUSE_MEDICAL（**不经 LLM**）
  ├─ intents.classify(question, payload)   ← 确定性规则，不用 LLM
  ├─ knowledge.search(question)            ← 关键词 + 2-gram，纯 Python
  ├─ facts = build_facts(payload, faq_hit)  ← 结构化事实包
  ├─ llm.narrate(facts)                    ← 无 LLM / 调用失败 → None
  ├─ guard.scan_output(text)               ← 命中禁用词 → 整段替换为拒答模板
  └─ actions.extract(question, facts)      ← FILL_ORDER_DRAFT / NAVIGATE
```

## 三、接口契约

### 3.1 `POST /api/assistant/chat`

权限：**FAMILY**（`@PreAuthorize("hasRole('FAMILY')"`）。ELDER / COMPANION / ADMIN → `403`。

> ELDER 走既有 `ElderReadOnlyInterceptor` 与 `@PreAuthorize` 双重拦截，本模块**不给老人开任何口子**。

**请求**（`AssistantChatDTO`）：

| 字段 | 类型 | 校验 | 说明 |
|---|---|---|---|
| `question` | String | `@NotBlank` `@Size(max=500)` | 用户问题 |
| `history` | List\<AssistantHistoryTurn\> | `@Size(max=12)` | 历史消息，**只透传不落库**。1 轮 = user 1 条 + assistant 1 条 = 2 条，故 6 轮 = **12 条**（见 D-3.7-5） |
| `orderId` | Long | 可选 | 给了则装配该单上下文；**归属校验不通过 → 3004** |
| `elderId` | Long | 可选 | 给了则校验是当前家属绑定的老人，否则 `2006` |

`AssistantHistoryTurn`：`role`（`user` / `assistant`）、`content`（`@Size(max=1000)`）。

**响应**（`AssistantChatVO`）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "answer": "……",
    "intent": "RECOMMEND_COMPANION",
    "actions": [
      { "type": "FILL_ORDER_DRAFT",
        "payload": { "elderId": 401, "elderName": "张*",
                     "hospital": "海南省人民医院",
                     "address": "海南省海口市秀英区秀华路19号",
                     "department": "心血管内科",
                     "visitTime": "2026-10-28 09:30:00" } },
      { "type": "NAVIGATE", "payload": { "path": "/family/order/step2" } }
    ],
    "sources": ["docs/api/03-order.md §13"],
    "degraded": false
  }
}
```

| 字段 | 说明 |
|---|---|
| `answer` | 自然语言回答。**必须已过输出护栏** |
| `intent` | `FAQ_PLATFORM` / `RECOMMEND_COMPANION` / `ORDER_STATUS` / `REFUSE_MEDICAL` / `UNKNOWN` |
| `actions` | 结构化动作；`FILL_ORDER_DRAFT` 的 `payload` **只带助手确实抽取到的字段** |
| `sources` | FAQ 条目的依据引用（`docs/api/xx.md §n`） |
| `degraded` | `true` 表示走了降级路径（无 LLM 或 LLM 调用失败） |

### 3.2 错误码（10xxx 智能助手，M14）

| code | 常量 | 含义 | 触发 |
|---|---|---|---|
| 10001 | `ASSISTANT_RATE_LIMITED` | 提问过于频繁，请稍后再试 | Redis 计数超 `rate-limit-per-minute` |
| 10002 | `ASSISTANT_UNAVAILABLE` | 智能助手暂时不可用，请稍后再试 | Python 不可用**且**本地 FAQ 兜底也失败 |
| 10003 | `ASSISTANT_QUESTION_ILLEGAL` | 问题内容包含违规表述，请重新描述 | 输入命中辱骂 / 违规引流词 |

**不占用** 9xxx（语义已固定为统计导出）。通用 `400` / `401` / `403` / `3004` / `2006` 复用。

### 3.3 配置（`nianglin.assistant.*`）

```yaml
nianglin:
  assistant:
    enabled: true
    service-url: ${AI_SERVICE_URL:http://127.0.0.1:8081}
    connect-timeout-ms: 3000
    read-timeout-ms: 60000
    rate-limit-per-minute: 10
    # 6 轮 = 12 条消息（user + assistant 各一条）
    max-history-messages: 12
    max-question-length: 500
    fallback-on-error: true
    # 本地兜底用的知识库路径（与 Python 侧读同一个文件）
    faq-path: ../ai-service/knowledge/faq.json
```

`AssistantProperties#validate()`（`@PostConstruct`，照 `MatchingProperties` 样板）：

- `rate-limit-per-minute ≥ 1`
- `max-history-messages ≥ 0`
- `max-question-length ≥ 1`
- `connect-timeout-ms ≥ 100` 且 `read-timeout-ms ≥ 1000`
- 任一不满足 → **启动失败**

### 3.4 限流

- Redis key：`assistant:rl:{userId}:{yyyyMMddHHmm}`（分钟粒度桶）
- `INCR` + `EXPIRE 60`
- 计数 > `rate-limit-per-minute` → 抛 `BusinessException(ResultCode.ASSISTANT_RATE_LIMITED)`
- **Redis 不可用时放行**（限流是保护措施，不是安全边界；Redis 挂了不该让助手整体不可用）→ 记 warn 日志

### 4.4 合规词表加载（fail-fast）

`paths.py#load_compliance_words()`：

1. 解析路径（环境变量优先）；
2. 文件不存在 → **抛 `ComplianceWordsError`**（服务启动失败）；
3. 逐行读取，忽略空行与 `#` 开头行；
4. `len(words) < 10` → 抛错；
5. `{"建议服用", "剂量"}` 不是子集 → 抛错。

**理由**（ADR-0020 决策 3）：词表读空 = 护栏静默失效 = 最危险的一类故障。它不会报错，只会让所有医疗回答放行，且看起来一切正常。

### 4.5 意图分类（确定性）

优先级短路，**从上到下第一个命中即返回**：

| 序 | intent | 触发条件 |
|---|---|---|
| 1 | `REFUSE_MEDICAL` | 命中医疗关键词表（见 §4.6） |
| 2 | `ORDER_STATUS` | 命中订单状态关键词（我的订单 / 到哪了 / 接单了吗 / 什么时候来 / 完成了没 / 催单 / 谁接了） |
| 3 | `RECOMMEND_COMPANION` | 命中推荐关键词（推荐 / 找个 / 安排 / 派个 / 派谁 / 哪个陪诊员 / 几位陪诊员 / 陪诊员推荐 / 陪诊员为什么 / 为什么合适 / 谁合适 / 找个师傅 / 匹配 …）。**刻意不用裸词「陪诊员」** —— 那会把「陪诊员资质怎么审核」也路由到推荐分支（见 D-3.7-6） |
| 4 | `FAQ_PLATFORM` | FAQ 检索最高分 ≥ 阈值 |
| 5 | `UNKNOWN` | 以上都不中 |

> **医疗意图排在第一位**：同时含「陪诊员」与「病情」的问题必须拒答，不能因为命中推荐词而放行。

关键词表放在 `intents.py` 顶部常量区，**纯数据、可单测**。

### 4.6 医疗关键词表（输入侧）

覆盖：诊断 / 确诊 / 得了 / 什么病 / 是不是 / 严重吗 / 什么药 / 吃什么药 / 能吃吗 / 剂量 / 用量 / 几次 / 一天几次 / 副作用 / 禁忌 / 高血压 / 糖尿病 / 肿瘤 / 癌 / 支架 / 化疗 / 手术 / 偏方 / 保健品有用吗 / 抑郁 / 焦虑 / 失眠 / 自杀 / 遗嘱 / 传染。

**只做「是否疑似医疗意图」的粗判**，不做诊断判断——判定的目的是**拒绝**，不是分类。

> ⚠️ 用**裸词**（「癌」「手术」「抑郁」「焦虑」）而不是只用长变体（「癌症」「抑郁症」）：
> 家属说的是「肺癌」「要不要做这个手术」「我最近很抑郁」，长变体匹配不上就等于没拦。

> ⚠️ 刻意**不含**「药」「医院」「治疗」「检查」这类宽泛词：`ComplianceCheckUtil` 的同一纪律（「已协助取药」是完全合法的过程记录）。

### 4.7 FAQ 检索（零依赖）

**FAQ 条目结构**（`knowledge/faq.json`，数组）：

```json
{
  "id": "faq-order-cancel-01",
  "intent": "FAQ_PLATFORM",
  "question": "下了单还能取消吗？",
  "keywords": ["取消", "退单", "不去了", "取消订单"],
  "answer": "……",
  "source": "docs/api/03-order.md",
  "anchor": "## 3. 家属取消"
}
```

**检索算法**（无分词库、无向量库）：

1. 用户问题取 **2-gram 字符集合** `G(q)`；
2. 对每条 FAQ：
   - `keyword_hit` = 问题中**子串包含**任一 keyword 的个数（每个 keyword 权重 3.0）；
   - `question_overlap` = `G(q) ∩ G(faq.question)` 的 Jaccard 相似度（权重 2.0）；
3. `score = keyword_hit_weight + question_overlap_weight`；
4. 取 top-3；**最高分 < 2.0 → 视为未命中**（`UNKNOWN`）。

「子串包含」对中文短问法足够稳（`取消`、`退单` 这类词几乎原样出现在提问里），且**可解释**——命中了哪个 keyword 可以直接显示。

> ⚠️ **因为 2-gram Jaccard 最大只到 2.0 分（恰好等于阈值），`keyword` 就是命中率的唯一实际通道** ——
> 它不是「调优项」，是「功能」。补关键词 = 补功能。
>
> 2026-10-21 起，关键词覆盖由**问法池**驱动：
> 30 条 FAQ × 6 条 = 179 条**大模型生成的模拟问法**（`ai-service/knowledge/faq-question-pool.json`），
> 召回率从 **34.4% 提到 97.2%**，由 `ai-service/tests/test_faq_coverage.py` 在 CI 里锁住。
> 工具与取舍详见 [V3.7-faq-question-pool.md](./V3.7-faq-question-pool.md)。
>
> ⚠️ 问法是**模拟数据不是真实用户数据** —— PRD 风险第 5 条据此**保持未关闭**。

### 4.8 LLM 抽象与降级

```python
class LlmProvider(Protocol):
    def narrate(self, system: str, user: str) -> str | None: ...
```

- `LangChainProvider`：包 `ChatOpenAI(base_url=..., api_key=..., model=..., timeout=...)`；调用异常 / 超时 → 返回 `None`。
- `NullProvider`：恒返回 `None`。**未配置 `LLM_BASE_URL` 时使用它。**

**降级行为**：`narrate` 返回 `None` → 直接用 FAQ 条目的 `answer` 原文作为 `answer`，`degraded = true`。

**未配置 LLM 不是错误状态** —— 服务照常启动、照常可用。

### 4.9 Prompt 规格

system prompt 必须写死以下约束（缺一条即视为未实现）：

1. 你是银龄伴诊平台的客服助手，只回答**平台服务规则**类问题；
2. **只能**基于给定的 `facts` 回答，**不得**引入任何外部医学知识；
3. **不得**给出诊断结论、用药建议、剂量、疗效判断；
4. 描述陪诊员时**必须**原样转述 `reasons` / `mismatches` / `notes` 三个字段，**不得**合并、不得美化；
5. `notes` 里写「未填写坐标，距离维度记 0」时，**必须**表达为「距离维度无法计算」，**不得**说成「距离近」「离得近」「就在附近」；
6. **不得**使用「已指派」「已分配」「自动派单」；推荐一律表述为「推荐仅供参考，最终由陪诊员本人确认接单」；
7. 回答末尾**不要**自行添加免责声明（由前端统一渲染）；
8. **用纯文本输出**，不使用 Markdown 标记（`**` / `##` / `- `）。

> ⚠️ 第 8 条的理由（V3.7 联调实测）：前端是 `{{ m.content }}` **纯文本渲染**
> （`white-space: pre-wrap` 只保留换行），**不解析** Markdown，也没有引 Markdown 渲染依赖。
> 模型一旦用 `**` 加粗，界面上就是字面量 `**命中理由**` —— 家属看到的是符号，不是排版。
> prompt 是「请求模型遵守」的约定、不是保证，所以**服务端另有一道兜底**
> （`service.normalize_plain_text`：只清标记、不动内容），两边都要有。
>
> ⚠️ 与第 5 条同源的另一条硬边界：**事实不足时模型不得硬凑**。
> 「推荐个陪诊员」但没有订单上下文时，事实包里根本没有候选，
> 模型会生成「**命中理由** - 现有事实中未提供具体陪诊员的画像…」这种三段空壳。
> 所以 `RECOMMEND_COMPANION` 且候选为空时**不调模型**，走确定性引导
>（对应 §五 已知限制 1：推荐是订单锚定的，没下单本版不支持，助手引导先成单）。
> `UNKNOWN` 同理 —— 固定澄清话术，不让模型自由发挥（契约见 `docs/api/13-assistant.md` §1.2）。

### 4.10 输出护栏

`guard.scan_output(text)`：

| 命中 | 处理 |
|---|---|
| 17 词禁用表任一 | **整段替换**为拒答模板（不是打码后放行） |
| 「已指派」「已分配」「自动派单」任一 | **词语级纠正**（已指派→推荐 / 自动派单→自动推荐）并追加免责句 —— 这是产品边界问题而非合规红线，纠正后语义仍正确，整段丢掉会让家属白问一次 |
| 「距离近」「离得近」「就在附近」等**距离措辞**任一 | **词语级纠正**为「距离维度无法计算（陪诊员尚未填写坐标）」—— v1.0.1 新增。陪诊员坐标全是空，距离维度恒为 0，把「算不出来」说成「很近」会让**正在挑陪诊员的家属**据此做决定（ADR-0016 决策 3）。⚠️ 这条纪律原先只写在 prompt 约束 5 里，**代码层零兜底** —— prompt 是「请求模型遵守」的约定，代码才是「模型不遵守也拦得住」的保证 |
| 空 / None | 回落到 FAQ 原文（降级路径） |

> ⚠️ **派单措辞与距离措辞不早退**：一段话可能同时命中两种。
> 早退会让「先命中派单措辞」的那段**跳过**距离纠正 ——
> 反而是「已指派…就在附近」这种最坏组合能漏出去。两种纠正都要跑。

**拒答模板**（固定文案，**来自共享资源文件** `backend/src/main/resources/compliance/refusal-template.txt`，
Java 与 Python 读同一份，所以两侧不会各说各话）：

```
这个问题属于医疗健康咨询，平台不提供医疗建议。请直接咨询接诊医生，或前往医院就诊。
```

> ⚠️ **模板本身不得含任何禁用词** —— 否则输出护栏会把拒答模板自己拦下，
> 家属看到的是一段莫名其妙的提示。Java 侧 `ComplianceCheckUtilTest` 与
> Python 侧 `test_guard.py` 各有一条断言专门守这个。

### 4.11 动作抽取

| 动作 | 何时产出 | payload |
|---|---|---|
| `FILL_ORDER_DRAFT` | 问题里抽到就诊信息时 | `elderId` / `elderName` / `hospital` / `address` / `department` / `visitTime`，**只带抽到的** |
| `NAVIGATE` | 有 `FILL_ORDER_DRAFT` 时 | `{ "path": "/family/order/step2" }`（无 `elderId` 时前端跳 step1） |

抽取规则（**正则 + 中文关键词，不依赖 LLM**）：

- `hospital`：包含「医院」的片段，或「去 XX 医院」
- `department`：包含「科」「室」「内科」「外科」等科室词的片段
- `visitTime`：匹配 `M月D日` / `YYYY-MM-DD` / `周X` / `上午|下午` + `X点`
  - ⚠️ **日期与时刻必须都抽到**才算抽到。只找到日期没找到时刻 → **留空**，
    **不补 `09:00:00`**（v1.0.1 修订）。那个时刻不是用户说的、是平台编的，
    而它会被前端写进草稿、最终成为订单的就诊时间 ——
    家属看到「下周三 09:00」多半不会意识到这个 09:00 是猜的。
    与「多位老人时不自动挑人」是同一条纪律：**猜错比不填更糟**。
  - 只找到时刻没找到日期 → 同样留空（相对日期必须锚在一个明确的「今天」上）。
- `elderId`：**只在 payload.elders 恰好只有一位时**自动填入；否则留空并由前端让用户选

## 八、已知限制（写进文档，不是 bug）

1. **陪诊员坐标全空** → 距离维度对所有候选人恒为 0，`notes` 会说「未填写坐标，距离维度记 0」。这是**如实反映「现在没有距离数据」**，不是缺陷（ADR-0016「待观察」）。助手**必须原样转述**，不得美化为「距离近」。
2. **FAQ 时效性靠人工维护** + 锚点校验脚本，不靠模型。
3. **限流阈值 10 次/分钟是拍板值**，无真实流量数据支撑。
4. **助手不查库**，工具数据是本次请求的快照。
5. **家属端没有可浏览的陪诊员列表**，所以「看看有哪些陪诊员」这类问题只能答「推荐需在下单后给出」。
6. `LLM_MODEL` 无默认值 → 未配置时即使配了 `LLM_BASE_URL` 也会走降级（**不报错**，避免配置半套时静默空转）。
