## 〇、这份预写承诺了什么

V3.3 回答的问题是：**「陪诊员能不能清楚掌握自己的工作、收入和服务质量？」**

V3.0 的现状：陪诊员端有接单大厅、订单列表、订单执行、收入、评价、个人资料六个页面，
但「我这个月做得怎么样」要自己数。

而**收入页现在是在前端算的**（`income.vue` 用 `reduce()` 自算总收入 / 待结算 / 已结算）——
这直接违反 roadmap 决策 G8「前端统计零自行计算」。本版的第一件事就是把它搬回后端。

## 二、接口契约

> 全部 `hasRole('COMPANION')` + 「`companionId == 当前用户`」。
> **不接收 `companionId` 入参** —— 同 V3.2 老人端的理由：少一个可以出错的地方。

| 端点 | 响应要点 |
|---|---|
| `GET /api/statistics/companion/me` | 本月完成单数 / 服务时长 / 完成率 / 平均评分 / 本月收入 |
| `GET /api/statistics/companion/me/trend?dimension=ORDER\|INCOME\|RATING` | 按天/周分桶的序列 + 区间汇总 |
| `GET /api/statistics/companion/me/profile` | 平均评分 / 完成订单 / 服务老人数 / 准时率 / 完成率 / 服务时长 / 擅长服务标签 |
| `GET /api/statistics/companion/me/income` | 订单金额 / 实际收入 / 待结算 / 已结算 / 费用构成（代垫 vs 服务费） |

### 2.1 口径定义（逐条写死，开工时复核）

| 指标 | 公式 | 数据来源 |
|---|---|---|
| 完成率 | `(COMPLETED + REVIEWED) / (COMPLETED + REVIEWED + CANCELLED)` | `companion_order`（**拒单不计入分母**） |
| 准时率 | `ARRIVE` 打卡时间 ≤ `visit_time` 的订单数 / 已接单订单数 | `order_checkin` JOIN `companion_order` |
| 服务时长 | `SUM(finish_time − start_time)`，仅计 `COMPLETED` + `REVIEWED` | `companion_order` |
| 服务老人数 | `COUNT(DISTINCT elder_id)` | `companion_order` |
| 平均评分 | 复用既有评分口径（`companion_profile.score` / `review_count`） | **不重算** |
| 擅长服务 | `companion_order.department` 维度 TOP N（N ≤ 5，**样本 < 5 单的科室不展示**） | `companion_order`（决策 3.3：来源于真实业务数据） |
| 本月收入 | `SUM(actualFee ?? fee)`，仅计 `COMPLETED` + `REVIEWED` | `companion_order` |
| 待结算 / 已结算 | 按 `payment_status`（`UNPAID` / `SETTLED`）分组 | `companion_order` |
| 费用构成 | `order_fee_item` 按 `item_type`（`ADVANCE` / `SERVICE`）分组求和 | `order_fee_item` |

### 2.2 D8 落地：不做「平台服务费」

迭代计划 §34 要求「订单金额 / 平台服务费 / 实际收入」三分，
但**现有费用模型里没有「平台服务费」这个口径** ——
只有 `fee`（合同服务费）、`actualFee`（结算金额）与费用项 `ADVANCE` / `SERVICE` 两型。

roadmap 决策 3.2 明写「不引入新的金额字段」，
所以本版**只做五项**（订单金额 / 实际收入 / 待结算 / 已结算 / 费用构成），**不引入平台服务费**。
代价与理由记录在 PRD 的「非目标」表里。

### 2.3 存量违规修正（必做）

- **`companion/income.vue` 的前端 `reduce()` 全部移除**，改为消费 `/income` 端点（决策 G8）。
- 页面**保留**（决策 3.4：新工作台不替换既有收入页），但两处数据来源**收敛到同一个 Service 方法**。
- E2E 加一条断言：`income.vue` 的「待结算」数字 == 后端口径（防止前端再算一遍）。

## 三、测试矩阵

| 层 | 锁住什么 |
|---|---|
| Service 单测 | 每条口径的公式；拒单不计入分母；准时率的分子分母；擅长标签的样本门槛 |

| E2E | 工作台四块内容渲染；`income.vue` 的数字与后端一致 |

**反向验证**：把「拒单不计入分母」改成计入 → 完成率单测变红。
