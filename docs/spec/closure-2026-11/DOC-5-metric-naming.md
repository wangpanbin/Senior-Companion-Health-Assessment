# DOC-5 · 完成率 / 区间字段命名收敛

> 批次：**B（用药与文档域）** · 级别：DOC · 来源：`reports/business-closure-final-assessment-2026-11-28.md` §DOC-5
> 错误码：**不新增**

## Problem Statement

两个统计口径漂移，都属于「同名不同义」：

### A. 「完成率」一名三义

| 出现位置 | 分母 | 代码 |
|---|---|---|
| 管理统计「完成率」 | ÷ **全部订单** | `StatisticsServiceImpl` |
| 陪诊员工作台「完成率」 | ÷ （**完成 + 取消**） | `CompanionStatisticsServiceImpl` |
| 运营驾驶舱「按时完成率」 | **按时完成** ÷ **已完成** | `MetricFormulas` |

三个都叫「完成率」（或高度相似），分母完全不同。看板并排放着会让人以为其中一个算错了。

### B. 「本区间」三种时间字段

| 场景 | 时间字段 |
|---|---|
| 管理统计 | `create_time`（下单时间） |
| 陪诊员端 | `visit_time`（就诊时间） |
| 结算台账 | `finish_time`（完成时间） |

文档里都写了（`docs/spec/metric-dictionary.md` 与 `docs/api/09-statistics-export.md` 各自说明），但**同一个词「本区间」在三个页面指三个不同的东西**，读者必须记住哪个页面用哪个字段。

## Solution

不改计算，只改**命名与文档表述**：

1. 三个「完成率」各自改名为互不歧义的名称；
2. 「本区间」在文档与接口说明里统一加后缀，指明时间字段。

**这是纯文档 + 文案改动，不动任何计算公式。** 因为公式本身各自都是对的，错的是「用同一个词指三件事」。

## User Stories

1. 作为评审人，我想三个完成率名字不同、含义清晰，这样我不会以为数据有错。
2. 作为评审人，我想「本区间」在哪个页面都写清是按哪个时间字段，这样我核对时不用猜。
3. 作为管理员，我想看到「订单完成率」而不是含糊的「完成率」，这样我知道分母是全部订单。
4. 作为管理员，我想看到「按时完成率」这个完整名称，这样我知道它衡量的是时效而非数量。
5. 作为陪诊员，我想我的「接单完成率」与管理员的口径区分清楚，这样我不会以为系统算错。
6. 作为陪诊员，我想收入页明确「按下单时间」还是「按就诊时间」，这样我对账时不会差一个月。
7. 作为财务，我想结算台账明确「按服务完成时间」，这样跨月订单不会算错周期。
8. 作为运营，我想同一份报表里的所有「区间」都标了字段，这样汇总不会串。
9. 作为数据分析，我想指标字典里每个 key 的「时间字段」是必填项。
10. 作为数据分析，我想同名指标不会有两个分母。
11. 作为前端开发者，我想接口文档写清时间字段，这样我在页面上标注不至于写错。
12. 作为前端开发者，我想改文案时知道要同步哪些页面。
13. 作为测试者，我想看到指标字典「双向一致性」检查仍通过。
14. 作为维护者，我想新增指标时必须填时间字段，这样不会再出现「同名不同源」。
15. 作为读者，我想指标字典里一眼能看出三个完成率的差别。

## Implementation Decisions

### A. 三个完成率改名

| 现名 | 新名 | 覆盖范围 |
|---|---|---|
| 完成率（管理统计） | **订单完成率** | `docs/spec/metric-dictionary.md`、`docs/api/09-statistics-export.md`、管理端页面文案 |
| 完成率（陪诊员工作台） | **接单完成率** | 同上（陪诊员台账） |
| 按时完成率（驾驶舱） | **按时完成率**（保持不变，本身已无歧义） | — |

- **指标字典 key 不改**（改 key 会触发 `check_metric_dict_parity.py` 双向校验与看板配置改动）。只改「人读面」的 label。
  - 若字典条目里有 `label` 字段，直接改 label；若无，则在说明列加「（即订单完成率）」。

### B. 「本区间」加后缀

在下列位置把裸「本区间」改为带字段后缀的表述：

| 位置 | 改为 |
|---|---|
| 管理统计相关说明 | 本区间（**按下单时间** `create_time`） |
| 陪诊员端相关说明 | 本区间（**按就诊时间** `visit_time`） |
| 结算台账相关说明 | 本区间（**按服务完成时间** `finish_time`） |

### C. 指标字典补「时间字段」必填

- `docs/spec/metric-dictionary.md` 的表格结构检查：若「时间字段」列已存在，确认每一行都填了；若不存在，**本单不新增列**（会触发校验脚本改动），改为在「口径说明」列内写明。

### 接口变更

- 无。纯文档 + 前端文案（前端文案改动需另开工单，本单只在文档里给出新名称）。

## Testing Decisions

## Out of Scope

- **不改任何计算公式**。
- 不改指标 key（避免破坏看板与双向校验）。
- 不改前端页面文案（需另开工单；本单给出新名称供前端对齐）。
- 不统一三种时间字段（它们各自都是合理选择，强行统一会破坏既有报表的含义）。

## Further Notes

- 这条的价值是「答辩时不会因为统计伎俩被追问」。三个不同的数都叫「完成率」，是最容易被抓的那类问题——**因为它们的和不一定等于 1，而评审人会先怀疑算错了**。
- **不要试图统一时间字段**：管理统计按下单时间是合理的（衡量获客与转化），陪诊员按就诊时间是合理的（衡量工作量），结算按完成时间是合理的（衡量何时该付钱）。三者不同是**设计**，不是缺陷——只需要说清楚。
