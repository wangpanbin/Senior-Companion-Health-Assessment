### (c) 看起来实现了、但实现方式可疑

#### Sp-c1 · 「距离近」只在 prompt 里有约束，**代码层零兜底** ★最严重

- **位置**：`ai-service/app/guard.py` `scan_output`（原只处理医疗词 + 派单词）
- **规格出处**：`docs/adr/0016` 决策 3；`ADR-0020` §九「**被单测锁死**『不得把「距离没法算」说成「距离近」』」；`docs/prd/PRD-V3.7-家属智能助手.md:93`「输出含「距离」但**不含**「距离近」「离得近」「就在附近」」
- **事实**：`scan_output("该陪诊员就在附近")` → `blocked=False`。现有单测只跑在**无 LLM 的降级路径**上，**LLM 路径零兜底**。ADR 声称「被单测锁死」，实际只锁住了另一半路径。
- **为什么这条最危险**：派单措辞只是把「推荐」说成「已安排」；**距离措辞是把「算不出来」说成「很近」** —— 陪诊员坐标目前全是空，距离维度恒为 0，正在挑陪诊员的家属会据此做决定。
- **处置**：✅ **已修** —— `guard.py` 新增距离措辞禁用词（7 个，取自 prompt 约束 5 与 PRD 验收条款的**并集**）与**词语级纠正**（替换为「距离维度无法计算（陪诊员尚未填写坐标）」，与 prompt 要求的表述逐字一致）。
  - **两种纠正不再互相早退**：一段话可能同时命中派单措辞与距离措辞，早退会让「先命中派单」的那段**跳过**距离纠正 —— 反而是最坏组合（两者叠加）能漏出去。
  - 替换串**自身不含任何禁用词**（含「距离」但不含「距离近」等），不会「纠正出来的文本又被自己拦下」。
  - 新增 5 组测试（含逐词参数化、组合命中、降级说明原文不误伤）。

#### Sp-c2 · `visitTime` 把用户没说的时刻补成 `09:00:00`

- **位置**：`ai-service/app/actions.py` `extract_visit_time`（原）
- **规格出处**：`docs/api/13-assistant.md:129`「`payload` 动作参数，**只含助手确实抽取到的字段**」；`docs/spec/V3.7-assistant-spec.md:401`「**只带抽到的**」
- **事实**：用户说「下周三」→ 抽到日期没抽到时刻 → 代码补 `09:00:00` → 前端写进草稿 → **成为订单的就诊时间**。而该函数**自己的 docstring** 写着「**日期与时刻必须同时存在**才算抽到 —— 猜一个时间比留空更危险（用户会以为平台已经安排好了）」，随后又补了一句「只找到日期没找到时刻 → 默认 09:00:00（工作日上午的常识默认值）」—— **函数体违反了自己上面那句话**。
- **判断依据**：项目自身的准则站在不猜这边 ——「多位老人时不自动挑人，**猜错人比不填更糟**」是同一条纪律。家属看到「下周三 09:00」多半不会意识到这个时刻是编的。
- **处置**：✅ **已修** —— 只找到日期没找到时刻 → 返回 `None`，`visitTime` 不进 payload，让家属在确认页自己补。
  - 复用的现成证据：前端 `applyDraft` 写的是 `payload.visitTime ?? orderDraft.visitTime`，**本来就支持缺省**；E2E 用的「下周三去海南省人民医院心内科」仍会出卡片（医院 + 科室 已抽到）。
  - 原 `test_extract_visit_time_defaults_to_morning_when_time_missing` 锁的是旧行为，改为断言 `None`，并新增「草稿里不得出现 visitTime」一条。

#### Sp-c3 · Java 本地兜底路径**漏了**派单措辞纠正

- **位置**：`backend/.../AssistantServiceImpl.java` `guardAnswer`（原）
- **规格出处**：`docs/api/13-assistant.md:236`「**本地兜底路径同样要过这道护栏**（Java 侧 `AssistantServiceImpl#guardAnswer`）—— 否则「Python 挂了就没人管」恰好成了绕过护栏的路径」
- **事实**：Java 侧只调 `ComplianceCheckUtil.firstHit()`（医疗词表）做整段替换，**没有**派单措辞的词语级纠正。契约明写要过的那道护栏，**只兑现了一半**。
- **处置**：✅ **已修** —— `guardAnswer` 补上派单措辞的词语级纠正 + 免责句（与 Python 侧 `ASSIGNMENT_WORD_FIXES` 同源同口径）。新增 `AssistantServiceImplGuardTest`（5 条）。
  - 做成 `static` 且**包级可见**：这段纯文本逻辑不该为了可测性把整个门面拉起来（门面构造要一整套依赖）。
  - ⚠️ 这三个词是**产品边界**清单（3 个词），**不是**合规词表 —— 合规词表（医疗 / 辱骂）是跨栈共享的单一真源文件。FAQ 答案里若混入这三个词，`tools/check_faq_anchors.py` 会先变红。

#### Sp-c4 · `degraded` 提示文案把「服务故障」说成「没接模型」

- **位置**：`frontend/src/views/family/assistant.vue`（桌面 / 移动两处模板）
- **规格出处**：`docs/api/13-assistant.md:112`「`degraded` 是否走了降级路径（未接入大模型，直接给标准答案原文）」
- **事实**：`degraded=true` 有**两种**成因 —— ① 没配模型 ② **Python 服务不可用、走 Java 本地兜底**（`AssistantServiceImpl:394` 置 `true`）。而前端文案断言「**当前为基础模式（未接入大模型）**」——第二种成因下这是**错的**：家属看到的是「平台没接大模型」，而不是「助手服务暂时不可用」。
- **处置**：✅ **已修** —— 文案只描述**事实**、不描述**原因**：「以下为平台标准答案原文（未经过大模型生成）」，两种成因下都成立。`docs/spec/V3.7-assistant-spec.md` §5.3 item 4 同步。
  - `degraded` **字段语义不变**（仍是「给了标准答案原文而不是模型答案」），契约无需改字段。

**Spec 轴结论**：(a) **3 条**（已修 3），(b) **1 条**（已修 1），(c) **4 条**（已修 4）。最严重的是 **Sp-c1** —— ADR 声称「被单测锁死」的那条纪律，实际只锁住了降级路径，**LLM 路径上模型可以自由地说「就在附近」**。
