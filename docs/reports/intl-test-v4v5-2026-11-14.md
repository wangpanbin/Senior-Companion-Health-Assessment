## 5 · 缺陷清单（Q9：只记录不改，修复与否由人工决定）

### DEF-1 · 订单详情页产生 `orderId=undefined` 请求（V4-4 相邻，中）

- **现象**：点「生成草稿并继续」时，前端额外发出 `GET /api/execution/undefined/checkins` 与 `GET /api/review/order/undefined`，后端返回 `参数格式不正确：orderId`（GlobalExceptionHandler WARN）。
- **影响**：两条无效请求 + 用户可见的红色错误 toast（与「草稿已生成」成功提示同时出现，观感矛盾）；功能本身不受影响。
- **复现**：登录 fam001 → `/family/order/1031` → 转入用药计划 → 填药名 → 生成草稿并继续。
- **证据**：`backend/logs/run.out` 2026-11-14 15:59:58 两行 WARN。
- **疑似根因**：跳转用药页时订单详情组件以 `undefined` id 触发回显请求（订单上下文被提前清空）。

### DEF-2 · 注销拒绝提示数字占位未填（V4-1，低）

- **现象**：有进行中订单点注销，toast 显示「您还有 **笔**进行中的订单，请先完成或取消后再注销」——数量缺失。
- **对照**：后端消息「存在进行中的订单，请先完成或取消后再注销」正常；弹窗内 alert 文案正常。
- **复现**：fam001（有 PENDING 订单）→ 我的 → 注销账号 → 填密码+确认短语 → 确认注销。
- **疑似根因**：前端模板 `{count}` 占位符未替换（如 `您还有 {n} 笔` 中 `n` 为 undefined）。

### DEF-3 · 未登录时错误弹窗堆叠（疑似存量，非 V4/V5 引入，低）

- **现象**：会话失效状态下打开工作台，十余个「未登录或登录已失效」对话框逐个堆叠，需逐个关闭。
- **证据**：首轮浏览器快照（2026-11-14 测试开始时）。
- **疑似根因**：多个并发请求各自触发独立 `ElMessage`/Dialog，缺少 401 统一拦截去重（`request.js` 拦截器可能对 SSE/轮询类请求未合并处理）。
- **备注**：发生在测试开始前的残留会话，与 V4/V5 改动无直接关联，故列为疑似存量。

## 6 · 观察项（不判缺陷）

1. **助手历史轮次影响叙述**：历史含医疗问法时，后续命中 FAQ 的问题被叙述层降级为保守话术（`intent=FAQ_PLATFORM`、`sources` 正常返回，但答案改为「属医疗建议范围无法回答」）。方向合规（红线-1 保守），但用户体验上「问过一次医疗问题后 FAQ 就不再给内容」。另：「胃镜检查前能吃饭吗」因关键词未覆盖「吃饭」走 `UNKNOWN` 澄清话术（FAQ 关键词含「吃东西」但不含「吃饭」）。
2. **运营参数 UI 钳制**：`el-input-number` 把 9999 静默钳到上限 1440（标准组件行为）；后端直传 9999 正确返回 400，两层防护一致。
3. **V5-B 无前端页面消费 `listExamPrep()`**：`api/examPrep.js` 已就位，入口为后续迭代（规格既定，`docs/api/14-exam-prep.md` §2 已注明）。本报告按「契约 + 消息 + 助手 FAQ」三面验证。
4. **结算导出**：ego-browser 未捕获到 download 事件（Blob 触发方式与自动化监听不兼容），端点直调返回合法 xlsx（7274B）；**用户已人工复验通过**。
5. **管理员无独立消息页**：`MEDICATION_ESCALATED` 仅达 API 层（`GET /api/message` 可见），AdminLayout 无消息中心入口（`linkUrl=null` 无落地页，规格如此）。
