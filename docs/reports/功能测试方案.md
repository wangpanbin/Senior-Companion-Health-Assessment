## 2 · 测试环境与前提

### 2.1 服务启动 / 停止

```powershell
# MySQL / Redis 是本机常驻服务，脚本不负责起
powershell -File tools/e2e/start-services.ps1    # 起后端 8080
powershell -File tools/e2e/stop-services.ps1     # 停 8080 的 Java 进程
python tools/e2e/l0_identity_gate.py             # 任何 E2E/探针前先跑：确认 8080/8081/5141 是本项目进程
```

- 前端：`pnpm -C frontend run dev`（Playwright 会自起 5141 并复用）。
- AI 助手服务：`ai-service/` 独立进程，端口 8081，**只监听 127.0.0.1**。
- Knife4j 在线文档（对照契约用）：`http://localhost:8080/doc.html`。

### 2.2 数据基线重置（**两人共用一套环境，这条最重要**）

```powershell
python tools/e2e/restore_clean_baseline.py            # dry-run，先看计划
python tools/e2e/restore_clean_baseline.py --execute  # 真删（二次确认）
```

- **你是写操作的主力**（下单、接单、打卡、审核、导出都会改库）：**每完成一个模块段落就重置一次**，不要攒到最后 —— 否则 UI 测试者的只读用例会读到被你改脏的数据。
- ⚠️ **错峰**：重置前和 UI 测试者打招呼（建议你跑下午 / 他跑上午，或按模块轮换）。他正在走查时你重置，他的页面会突然"数据变了"。
- ⚠️ 破坏性脚本默认 dry-run；出现「待删超 30% 或 500 行」守卫时**停下来核对**，不要随手 `--force`（旧版脚本曾因此误删 629 行种子数据）。
- 跑 Playwright 写路径 spec 时，夹具会自动 `snapshot → 跑 → restore`；**写路径靶子必须在 `tools/e2e/fixture.py` 白名单内**（`sys_user` 白名单 = id `1,2,101,201-230,301`），否则污染本地库且 restore 不会还原。

| 角色 | 账号 | user_id | 用途 |
|---|---|---|---|

- 权威出处：[`docs/agents/FRONTEND_CONTRACT.md` §10.7](../agents/FRONTEND_CONTRACT.md)。

### 2.4 登录与令牌（踩过坑的三条）

1. **验证码一次性**：`GET /api/auth/captcha` → Redis 键 `captcha:<key>`（TTL 300 秒，`getAndDelete` 取出即删）。自动化直取 Redis，**不要 OCR**；双发登录必失败（见 FN-01-03）。
2. **accessToken 有效期只有 120 分钟**：探针 / E2E 的令牌隔几小时再用会全部 401，报错文案只说"未登录或登录已失效"，**极易误判成鉴权回归**。开跑前重跑 `pnpm -C frontend exec playwright test --project=setup` 重新落令牌。
3. **密码版本 `ver`**：改密 / 封禁会 `+1` 使旧令牌全部失效；登出只拉黑当前设备的 `jti`（按设备登出）。测"改密后旧令牌是否失效"必须用这条判据。

### 2.5 探针与自动化工具（你的主力武器）

| 工具 | 用途 | 前置 |
|---|---|---|
| `python tools/e2e/probe_api.py` | 接口冒烟探测 | 先 `start-services.ps1` + 先跑 Playwright `--project=setup` |
| `python tools/e2e/probe_access_matrix.py` | **越权矩阵**：25 端点 × 4 角色 = 100 次真实 HTTP，0 违规判据 | 同上 |
| `python tools/e2e/probe_backend_gaps.py` | 后端功能缺口探测 | 同上 |

| `pnpm exec playwright test --list` | 只列用例不执行（核对覆盖面） | — |

> 探针的令牌 TTL 120 分钟（§2.4），过期会报 `[EXPI]` 并指路重跑 setup —— 看到全 401 先怀疑令牌过期，再怀疑鉴权回归。

### 2.6 AI 助手服务与 LLM 模式

- `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` **留空 = 降级模式**：助手照常可用，回答直接给 FAQ 原文（响应带 `degraded=true`）。**降级模式是默认测试对象。**
- **可选**：若维护者已配置 LLM key，追加 FN-12 中标注「可选」的流式对话用例；未配置则在报告注明"LLM 真实调用未覆盖"，不算未完成。
- `LLM_BASE_URL` 与 `LLM_MODEL` **必须同时配**才启用 LLM —— 只配一半会静默空转（`ai-service/app/config.py` 的注释明写）。

### 2.7 种子数据（断言条数的唯一依据）

以 [`docs/agents/FRONTEND_CONTRACT.md` §10.8](../agents/FRONTEND_CONTRACT.md) 为准（实测于 2026-10-21，真源 `backend/sql/V2__seed_data.sql`）：

- 订单共 **64**：`PENDING` 6 / `ACCEPTED` 8 / `IN_SERVICE` 4 / `COMPLETED` 12 / `REVIEWED` 31 / `CANCELLED` 3；待接单样本 id `1001`–`1006`，费用 98/128/158/188/218/**248**。
- `fam001` 名下订单仅 **2** 条（`1031` REVIEWED、`1001` PENDING），绑定老人 401 + 一条 `UNBOUND` 解绑边界样本指向 431。
- 服药任务共 **520**：`MISSED` 193 / `TAKEN` 327 / `PENDING` 0；老人 401 共 12 条（MISSED 7 / TAKEN 5）。
- 投诉共 **32**：`PENDING` 9 / `PROCESSING` 7 / `RESOLVED` 11 / `REJECTED` 5。
- 资质申请共 **30**：`APPROVED` 25（可接单 22、休息 3）/ `PENDING` 3 / `REJECTED` 2。

> ⚠️ **核对用只读 SQL**（`SELECT ... GROUP BY`），不要 `MAX(id)-N` 猜；**不要照抄更早文档的旧数**（这一节曾经错过，2026-10-21 修正）。数字对不上先怀疑"数据漂移"，查清再报缺陷。
> ⚠️ PowerShell 取 mysql 中文会乱码，判据尽量放在**数字 / 枚举名 / id** 上。

## 4 · 用例表约定

| 列 | 含义 |
|---|---|
| 编号 | `FN-<模块>-<序号>`，issue 与截图文件名都用它 |

## 6 · 注意事项

### 6.1 共同合规红线（两份文档都适用，**违反即 P0**）

出处：[`AGENTS.md` §0.1](../../AGENTS.md)，这是计划书里的硬约束，不是风格偏好。

1. **不做诊断、不开药方**：接口或页面出现"建议服用""推荐剂量""诊断为""可能是 XX 病"类表述 → **P0**。药品字典只返回通用信息（名称/规格/通用说明），免责声明必须存在。相关回归用例：FN-05-07、FN-03-13、FN-04-05、FN-12-02。
2. **隐私最小化**：接口返回的手机号/身份证/姓名按场景脱敏（`MaskUtil`）；**localStorage 禁止写入密码、身份证号、完整手机号**。
   > 已记录的唯一豁免：`GET /api/order/{id}` 详情返回**全名**是刻意设计（列表脱敏、详情全显，见 `AGENTS.md §0.1` 第 2 条）。别误报，也别拿它类推其它接口。
3. **一期不做**：在线支付、地图导航入口 → 发现即 P0。IM 已按 **M13 订单聊天**放开（仅限按订单的家属↔陪诊员），出现"自由加好友式 IM"才是缺陷。
4. **第二个技术栈的依赖红线**：`ai-service/requirements.txt` 经人工批准并冻结（ADR-0020），**测试中发现缺依赖不要自己装**，报维护者。

### 6.2 功能测试专属注意事项

1. **先跑前置门禁（§3）再开测**；门禁红了报维护者，不要绕过。
2. **你是写操作主力**（§2.2）：每完成一个模块段落就 `restore_clean_baseline.py --execute` 重置，并**和 UI 测试者错峰**，别在他走查时重置。
3. **断言前先确认数据没被自己改脏**：条数类断言（§2.7）与"重置后再核"绑定执行。
4. **越权用例必须带合法 payload**（§FN-14 警告）：否则 403 是参数校验给的，鉴权根本没跑到 —— 那是**假红**，放宽它就变**假绿**。
5. **令牌过期 ≠ 鉴权回归**（§2.4）：探针全 401 先重跑 `--project=setup`。
6. **三套测试条数口径别混用**：`@Test` 方法数 / 测试注解总数 / surefire 实跑数 —— 报告里引用数字时注明口径与本次运行输出，**不要手抄旧文档**（AGENTS.md §11 同款要求；需要仓库规模数字先跑 `python tools/repo_metrics.py` 并注明基线 ref）。
7. **种子条数是设计不是 bug**：`fam001` 2 条订单、投诉 32 条等都是种子设计（§2.7）；对不上先重置、再查真源 `V2__seed_data.sql`，查清再报。
8. **发现"假红"先查请求是否真的到达鉴权层**；**不要为了让用例变绿放宽断言**（BUG_LIST §1 的原始教训）。
9. **issue / 截图 / 报告里不出现明文口令、真实手机号、身份证、完整 JWT**；日志片段贴之前先脱敏。
10. **改了 FAQ 知识库才需要**跑 `python tools/check_faq_anchors.py` —— 测试者一般不改，只报缺陷。
11. **新发现的业务规则与文档冲突**：以现实代码为准记录缺陷并提示冲突，**不要擅自"修"文档**（AGENTS.md §12）。

## 7 · 缺陷记录流程

1. **每个失败用例开一个 GitHub issue**，标题格式：`[功能][P1] FN-03-06 非法状态流转未被拒绝`。
2. **标签**：按 [`docs/agents/triage-labels.md`](../agents/triage-labels.md) 五标签流转 —— 新建默认 `needs-triage`；确认后改 `ready-for-agent`（给 AI 修）或 `ready-for-human`（要人拍板）；不修 `wontfix`；信息不足 `needs-info`。
3. **严重度定义**（写进 issue 正文）：

| 级别 | 定义 | 本项目示例 |
|---|---|---|
| **P0** | 主流程不可用 / **越权可写** / **违反合规红线** | ELDER 能写、非法状态流转成功、回答里出现用药建议 |
| **P1** | 主流程可用但逻辑错误 | 评分快照口径错、导出取消被记 500 |
| **P2** | 次要边界错误 | 分页边界参数 500 |
| **P3** | 体验/文案建议 | 错误提示措辞不一致 |

4. **issue 正文模板**：

```markdown
用例编号：FN-xx-xx
严重度：P0/P1/P2/P3
环境：后端 8080 / 基线是否重置过 / 令牌是否刚签发
复现步骤：
1. …
2. …
预期（契约出处：docs/api/xx.md §x.x）：…
实际：…
证据：响应片段（已脱敏）/ 截图路径 / 只读 SQL 结果
是否复现：3/3
备注：是否需要转 UI 测试者
```

5. **禁止**：issue 里贴真实手机号 / 身份证 / 口令 / 完整 JWT / 堆栈里的内网信息。
6. 修复后的**复测**在 Day4 完成；复测通过关闭 issue 并在执行报告记一行；**回归**：修过的点至少重跑对应模块的 P0 用例。
