## 二、背景与目标

### 2.1 要解决的产品问题

**家属要回答「找个靠谱的陪诊员」和「这流程怎么走、这钱怎么算」，今天这两件事都没有入口。**

| 家属的处境 | 平台今天的形态 |
|---|---|
| 找不到合适的陪诊员 | 家属端**没有可浏览的陪诊员列表**（`/api/order/hall` 是陪诊员专属）。订单进大厅后，家属只能在订单详情页看 V3.4 的「系统正在为你匹配」卡片 —— 那是规则引擎的五维分，**是给「看」的，不是给「问」的**：家属不知道该问什么，也不知道匹配结果该怎么理解 |
| 规则看不懂 | 平台规则散落在 `docs/api/*.md` 与 `plan.md` 里，**没有任何问答入口**。费用口径（工作日 `128.00`、夜间或周末 `158.00`）、取消规则、投诉入口全靠人肉翻文档 |
| 没人可问 | 家属↔陪诊员的订单聊天（M13，`/api/chat/**`）是**订单内双方沟通**，不是平台规则问答；老人账号只读、管理员仲裁只读，都不能回答「这单多少钱」 |

这不是「缺一个聊天框」的问题，是**平台没有把「可解释的匹配结果」和「可检索的服务规则」翻译成家属能直接消费的话**的问题。

而且这里有一条不能含糊的红线：家属端的助手一旦被当成「医疗咨询入口」，项目就踩了 AGENTS.md §0.1-1（不做诊断、不开药方）。所以本版不是「加个 AI 客服」，而是**在明确边界内把已有事实讲清楚**：

1. **问题与答案**都由仓库既有事实推导（FAQ 锚点 + V3.4 的推荐结果）；
2. **排序永远由 Java 规则引擎负责**，助手只做叙述；
3. **助手只填下单草稿，永不自动建单**；
4. **医疗类提问固定拒答**，引导线下就医。

### 2.2 目标

1. 家属用自然语言提问，能拿到**可溯源**的平台规则答案（每条回答能展开看到依据指向 `docs/api` 的哪个锚点）；
2. 说到「帮我找个陪诊员」时，助手能把就诊信息回填进下单草稿；订单建成后由 V3.4 的规则引擎给出候选，助手负责把「为什么是他」讲成人话；
3. 医疗类提问**必拒答**，且拒答发生在模型生成之前（输入侧拦截，不经 LLM）；
4. 无模型 / 断网 / 模型报错时，助手**功能完整可用**（降级为 FAQ 原文直出），评审现场不依赖外网、key 与配额；
5. 「不建单、不改排序、不碰医疗」三条硬边界写进产品口径，且**可被测试锁死**，而不是靠约定。

### 2.3 目标对应的用户故事（承接 V3.6 的 60 号之后）

| # | 用户故事 | 落在哪 |
|---|---|---|
| 61 | 我想知道平台怎么收费、怎么取消、怎么投诉，不用翻文档 | FR-Chat（FAQ 问答） |
| 62 | 每个答案都能告诉我依据在哪 | FR-Chat（`sources` 溯源） |
| 63 | 我说「帮我找个陪诊员」时，助手能接住需求并接着下单 | FR-Draft + FR-Recommend |
| 64 | 助手推荐的陪诊员有理由，不是黑盒 | FR-Recommend（`reasons` / `mismatches` / `notes` 三段转述） |
| 65 | 推荐不等于派单，接单权仍在陪诊员 | §四.4（推荐 ≠ 派单） |
| 66 | 我问病情问题时，助手明确拒绝并引导线下就医 | FR-Guard（`REFUSE_MEDICAL`） |
| 67 | 模型服务不可用时，我还能问到标准答案 | FR-Fallback（`degraded=true`） |
| 68 | 我问得太频繁时，助手拦住我而不是被刷爆 | FR-Limit（`10001`） |
| 69 | 我在助手里说的就诊信息不会变成一堆垃圾订单 | FR-Draft（只填草稿，不建单） |
| 70 | 我的对话内容不会被存进平台数据库 | §四.5（隐私口径） |

### 2.4 本版不追求的东西

助手的价值上限由两件事决定：**它只能讲仓库里已有的事实**，以及**推荐质量由规则引擎决定，不由模型决定**。
本版不追求「更聪明的回答」，只追求「回答不出错、错了能追到出处」。

## 三、功能需求

### FR-Chat · 平台常用问题问答

| 项 | 内容 |
|---|---|
| 用户故事 | 作为家属，我想用大白话问平台的收费、取消、投诉规则，并拿到能溯源的答案 |
| 交付 | 家属端 `/family/assistant` 页面（首页与订单详情各一个快捷入口）+ FAQ 25–30 条 + 每条回答带 `sources` 指向 `docs/api` 锚点 |
| 关键约束 | 意图分类与 FAQ 检索**不依赖 LLM**（确定性规则 + 关键词 / 2-gram 检索，零向量库）；回答**只能基于给定事实包**；检索最高分低于阈值即判「没找到」，如实说不确定 |
| 边界与例外 | FAQ 未覆盖的平台规则**不猜**；未命中时给不出答案就给出人工入口，而不是硬凑一句 |
| 验收 | 黄金问答集全绿；每条答案的 `sources` 指向**真实存在**的文档锚点；未命中时不产出编造答案 |
| 不做什么 | 不做医疗诊断与用药建议；不做超出平台服务规则范围的任意知识问答；不引入向量库 / embedding / 分词库；FAQ 不用 YAML 存（避免新增 `PyYAML` 依赖） |

### FR-Recommend · 陪诊员推荐叙述

| 项 | 内容 |
|---|---|
| 用户故事 | 作为家属，我想知道该给哪位陪诊员找，并知道为什么是他 |
| 交付 | 引用 V3.4 的候选推荐结果（`GET /api/order/{id}/recommend-companions`，仅下单家属）并转述；订单详情页与助手内都能看到同一份候选 |
| 关键约束 | **排序永远由 Java 规则引擎负责**；助手**不重排候选、不改维度分与总分、不补充候选结果之外的事实**；`reasons`（命中理由）/ `mismatches`（算了没命中）/ `notes`（数据缺失没法算）**三段分别转述，不合并** |
| 边界与例外 | 降级说明（如「未填写坐标，距离维度记 0」）**必须原样转述**，不得美化为「距离近」；**无订单不推荐**（推荐天然是订单锚定的）；非下单家属 → `3004` |
| 验收 | 叙述**必含**可解释理由；`distanceScore=0` 且 `notes` 含「未填写坐标」时，输出含「距离」但**不含**「距离近」「离得近」「就在附近」；输出不出现「已指派 / 已分配 / 自动派单」 |
| 不做什么 | 不自动派单、不自动接单、不改订单状态、不给陪诊员重新打分或排序、不替家属拍板人选 |

### FR-Draft · 就诊信息回填下单草稿

| 项 | 内容 |
|---|---|
| 用户故事 | 作为家属，我用一句话把就诊信息告诉助手，它帮我把下单信息填好，剩下我自己确认 |
| 交付 | 从对话中抽取就诊信息 → 回填既有下单草稿（`setElder` / `setVisit`）→「去确认下单」进入既有下单三步流程 |
| 关键约束 | 助手**只填草稿，永不自动建单**：不调用下单接口、不产生任何订单记录；**只回填确实抽到的字段**；回填由用户点击按钮触发，不由助手自动写入 |
| 边界与例外 | 家属绑定多位老人且未指明是谁 → **不猜**，留空由用户选；抽不到就诊时间不影响其它字段回填 |
| 验收 | 回填后进入下单流程的字段与对话内容一致；**下单之前订单数不变**（助手不产生任何订单记录） |
| 不做什么 | 不替用户提交订单；不代用户确认；不自动下单、不自动支付、不自动联系陪诊员 |

### FR-Guard · 合规护栏

| 项 | 内容 |
|---|---|
| 用户故事 | 作为平台，我需要助手在任何情况下都不给医疗建议 |
| 交付 | 三层护栏（输入侧 / 提示词侧 / 输出侧）+ 固定拒答模板 + 派单类禁用文案拦截 |
| 关键约束 | 详见 §四；**医疗意图在意图分类里排第一位** —— 同时含医疗词与推荐词的问题必须拒答，不能因为命中推荐词而放行 |
| 边界与例外 | 命中即拒、**不打码后放行**（打码后读者仍能猜出原意，这是仓库既有纪律） |
| 验收 | 任何医疗类提问**不可能**得到含剂量 / 诊断结论 / 疗效判断的回答；输出侧命中后**原句不残留**；拒答文案前后端一致 |
| 不做什么 | 不做「先给个建议再提醒注意安全」；不在拒答里附带任何倾向性医学表述；不为「更聪明」放松任何一层 |

### FR-Fallback · 无模型降级

| 项 | 内容 |
|---|---|
| 用户故事 | 作为家属，即使模型服务不可用，我也要能问到标准答案 |
| 交付 | 未配置模型 / 断网 / 超时 / 模型报错 → **直接返回 FAQ 条目原文**，`degraded=true` |
| 关键约束 | 降级路径与主路径**同构**（不是「主路径 + 一个补丁」）；**未配置模型不是错误状态**，服务照常启动、照常可用 |
| 边界与例外 | 模型服务不可用**且**本地 FAQ 兜底也失败 → `10002`（不返回 500） |
| 验收 | 不配模型时端到端仍能完成一次完整问答；降级路径返回的文本**同样过输出护栏**，不因「没走模型」而放行 |
| 不做什么 | 不做「模型不可用则整个助手不可用」；不因此放宽任何护栏；不做无限重试 |

### FR-Limit · 限流

| 项 | 内容 |
|---|---|
| 用户故事 | 作为平台，我需要有人刷爆助手时能被拦住，而不是让服务整体不可用 |
| 交付 | 每用户每分钟 **10 次**上限（配置项 `rate-limit-per-minute`），超限 → `10001` |
| 关键约束 | 限流是**保护措施，不是安全边界**：Redis 不可用时**放行**并记 warn 日志；计数键按「用户 + 分钟桶」 |
| 边界与例外 | 阈值是配置项，启动期校验；超限**不降级为 FAQ 直答**，直接拒答并提示稍后再试 |
| 验收 | 超限 → `10001`；Redis 不可用 → 放行 |
| 不做什么 | 不做全局总配额、不做按 IP 限流、不做封禁账号（那是 M9 管理后台的事） |

### 助手端点清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/assistant/chat` | `FAMILY`（仅家属） | 助手问答；ELDER / COMPANION / ADMIN → `403`；未登录 → `401` |

> 模块路径用 `/api/assistant/**`，**不复用** `/api/chat/**` —— 后者已被 M13 订单聊天占用（ADR-0011）。
> 助手的**内部**计算服务不直接暴露给浏览器，浏览器只与 `/api` 说话。

### 助手界面的口径约束

| 位置 | 内容 | 口径约束 |
|---|---|---|
| 页面顶部 | 常驻免责声明一行 | 「本助手只解答平台服务规则问题，不提供医疗诊断与用药建议」 |
| 每条回答下方 | 轻量免责 + 可展开的依据 | 依据指向 `docs/api` 锚点 |
| 推荐叙述 | 脱敏姓名 + 五维得分 + 三段说明 | 必带「推荐仅供参考，最终由陪诊员本人确认接单」；**不出现**「已指派」「已分配」「自动派单」 |
| 草稿回填卡 | 字段清单 + 「去确认下单」按钮 | **只有点击按钮才写草稿并跳转** |
| 降级提示 | 「当前为基础模式（未接入大模型），以下为标准答案」 | 仅 `degraded=true` 时出现 |
| 路由元信息 | `module: 'M14'`、`roles: ['FAMILY']`、`elderlyHidden: true` | 老人模式隐藏该入口（ELDER 本就无权限） |

## 四、合规边界（本版重点）

### 4.1 与 `plans/迭代计划.md` §60 三档的对照

| 档位 | §60 原文 | 本助手的关系 |
|---|---|---|
| 允许 | 运营数据分析 / 用户反馈总结 / 投诉文本归纳 / 服务质量分析 / 管理员辅助决策 | 「解答平台常用问题」是**平台服务规则的转述**，不引入任何外部知识，落在允许侧 |
| **谨慎使用** | **订单智能推荐 / 陪诊员匹配 / 异常检测** | **「向家属推荐陪诊员」正落此档** → 必须配护栏（本章即护栏） |
| 禁止 | 疾病诊断 / 疾病预测 / 治疗建议 / 药物推荐 / 药物剂量调整 / 医疗风险诊断 | **一律不碰**。医疗类提问**固定拒答**并引导线下就医 |

同时遵守 §61.3「AI 医疗诊断」明确禁止：症状诊断 / 疾病预测 / 处方推荐 / 药物推荐 / 治疗方案；
以及 §40「V3.4 后续 AI 方向」：优先考虑运营分析、异常总结、服务质量分析、用户反馈归纳、管理员辅助决策。

> **为什么必须新开 V3.7 / M14 / 新 ADR**：`docs/spec/V3.x-roadmap-spec.md` 与 `docs/spec/V3.4-matching-spec.md`
> 两处明写「V3.4 第一阶段不引入 AI 模型」。所以本能力**不能塞进 V3.4** ——
> 否则后来的开发者会以为那条约束已经被某个补丁解除了（ADR-0020 决策 1）。

### 4.2 必须拒答的问题类型清单

下表列的是**家属可能问、助手必须拒答**的类型与典型问法。处置统一为：**助手返回固定拒答模板 + 引导线下就医**（咨询接诊医生 / 前往医院就诊）。

| # | 问题类型 | 典型问法 | 处置 |
|---|---|---|---|
| 1 | 症状判断 | 「这个症状是不是 XX 病」 | 输入侧命中医疗意图 → 固定拒答模板 |
| 2 | 疾病预测 / 预后 | 「会不会发展成 XX」 | 同上 |
| 3 | 用药选择 | 「吃什么药好」「要不要吃 XX」 | 同上 |
| 4 | 剂量 / 用量 / 频次 | 「一次吃几片」「一天几次」 | 同上 |
| 5 | 疗效判断 / 是否继续服药 | 「这药有没有效」「要不要停」 | 同上 |
| 6 | 处方 / 开药 | 「帮我开药」「能配药吗」 | 同上 |
| 7 | 治疗方案 | 「要不要做这个手术」 | 同上 |
| 8 | 保健品 / 偏方 | 「这个保健品有用吗」 | 同上 |
| 9 | 副作用 / 禁忌 / 相互作用 | 「能不能和另一种一起吃」 | 同上 |
| 10 | 严重程度 / 风险分级 | 「严不严重」「有没有危险」 | 同上 |
| 11 | 辱骂 / 违规引流 | —— | 不进入模型，直接拒绝受理（`10003`） |

**固定拒答模板**（前后端一致，与工程契约同稿）：

```
这个问题涉及病情判断和用药建议，平台不能给医疗建议。
请直接咨询接诊医生，或前往医院就诊。
```

> 拒答模板之外**不再附带任何医学内容** —— 哪怕是「常见做法是……」这类补充，也是把平台的拒答变成了半吊子问诊。

### 4.3 三层护栏

| 层 | 位置 | 行为 | 锁死方式 |
|---|---|---|---|
| 1 输入 | 助手的输入扫描 | 医疗意图 → **直接返回固定拒答模板，不经 LLM**；辱骂 / 违规引流 → `10003` | Python 单测 + Java 单测 |
| 2 提示词 | 叙述用系统提示词 | 写死：只基于给定事实回答；不引入任何外部医学知识；不给诊断结论 / 用药建议 / 剂量 / 疗效判断；**必须原样转述 `reasons` / `mismatches` / `notes`**，不得合并、不得美化（距离措辞与派单措辞另见 §4.4） | 黄金问答集 |
| 3 输出 | 助手的输出扫描 | 命中医疗建议类禁用词 → **整段替换**为拒答模板；命中「已指派 / 已分配 / 自动派单」→ 整段替换为推荐免责话术 | 单测断言原句不残留 |

**命中即拒，不打码后放行**：打码只会把原意留在句子里（读者仍能猜出来），却让人误以为内容已经过滤。

**词表单一真源**：医疗建议类禁用词从 Java 侧硬编码改为**共享资源文件**，
Java 与 Python 两侧读**同一份**；两侧都在启动期 fail-fast（读不到 / 词数过少 / 缺少关键词 → 启动失败）。
理由是「词表读空 = 护栏静默失效 = 最危险的一类故障」：它不报错，只会让所有医疗回答放行，而且看起来一切正常。

### 4.4 推荐 ≠ 派单（文案口径）

**推荐永远不改变订单状态，接单权始终在陪诊员手里。** 助手的推荐叙述与 V3.4 的候选卡片必须标注：
「推荐仅供参考，最终由陪诊员本人确认接单」。

| 禁止出现 | 原因 |
|---|---|
| 「已指派」「已分配」「自动派单」 | 那是产品边界的改变，不是文案问题 |
| 「系统已为您锁定该陪诊员」 | 与「推荐 ≠ 派单」直接冲突 |
| 「距离近」「离得近」「就在附近」 | 把「距离**没法算**」说成「距离**不匹配**」的同款错误 —— 当前陪诊员坐标全空，距离维度对所有候选人恒为 0 |

### 4.5 隐私边界

| 项 | 口径 |
|---|---|
| 对话历史存放位置 | **浏览器 `sessionStorage`**，只存 `{role, content}`，超过 6 轮丢最旧 |
| 后端是否落库 | **不落库、不新增表、不动 Flyway 迁移**（数据库迁移已冻结，见 [`功能拓展规划.md`](功能拓展规划.md) §2.1） |
| 送入模型服务的内容 | 本次请求的**最小事实包**：老人脱敏名、订单必要字段、候选五维得分与三段说明、最近订单摘要 |
| 完整手机号 / 身份证号 | 不进入助手上下文、不进入日志、不返回给前端（仓库既有脱敏纪律：先脱敏再拼日志） |
| 用户令牌 | **不进入模型服务侧** —— 助手计算服务无状态、无鉴权、无数据库连接，不持有任何令牌 |
| 计算服务暴露面 | 仅本机监听，不直接对浏览器开放；浏览器只与 `/api` 说话 |

## 五、非目标（本版明确不做）

| 不做 | 原因 |
|---|---|
| 医疗诊断 / 用药建议 / 剂量调整 / 疗效判断 | §60 禁止档 + §61.3 + AGENTS.md §0.1-1（不做诊断、不开药方） |
| 自动派单 / 自动建单 | 「推荐 ≠ 派单」；助手若为出推荐而先建单，那些 PENDING 单会出现在**陪诊员大厅**，挤占真实供给 |
| 无订单推荐（先推荐、后下单） | 匹配的七个输入字段全部来自订单；没有订单就没有科室、就诊时间、坐标、区域码 —— 五维里塌陷四维，排序必然失真 |
| 向量库（FAISS / Chroma）+ embedding 的 RAG | 领域只有 25–30 条 FAQ，语义检索收益远小于依赖成本（模型下载、CI 变慢、评审机器装不上）；关键词 + 2-gram 检索可解释、可单测、零依赖 |
| 流式输出（SSE） | 收益（少等几秒）不抵复杂度（新增 SSE 通道 + 改前端渲染 + 改转发）；单次请求覆写 60s 超时足够 |
| 多轮自主 Agent（自主选工具） | 在「谨慎使用」档里引入无法写单测的行为面；决策链必须**可审计**、写死在代码里 |
| 数据库迁移 / 新增表 | 数据库迁移已冻结；对话历史放前端 `sessionStorage` |
| 给老人账号（ELDER）开放 | 老人账号默认只读；本模块不给老人开任何口子 |
| 给陪诊员 / 管理员开放 | 本版只做家属端（`FAMILY`）；管理员辅助决策属 §60 允许档的其它方向，不在本版 |
| 在线支付 / 地图导航 | 一期红线（AGENTS.md §0.1-3），本助手不涉及 |
| 把助手做成通用知识问答 | 只答平台服务规则类问题；超出范围如实说「没找到」 |
| 让助手每次回答都回调后端做合规校验 | 每答一次多一次网络往返；合规词表应是**共享文件**，不是共享接口 |

## 六、验收与门禁

### 6.1 功能验收项

- [ ] 家属可用自然语言问到平台常用问题，答案带可展开的 `sources` 锚点
- [ ] 意图分类与 FAQ 检索**不依赖 LLM**（无模型环境下同样可用）
- [ ] 提到「找个陪诊员」时，助手回填下单草稿并进入既有下单三步流程
- [ ] 回填只带**确实抽到**的字段；绑定多位老人且未指明时**不猜**
- [ ] 推荐叙述含可解释理由，且 `reasons` / `mismatches` / `notes` **三段分别转述**
- [ ] 无模型 / 断网 / 模型报错 → 返回 FAQ 原文且 `degraded=true`
- [ ] 超限 → `10001`；Redis 不可用 → 放行
- [ ] 助手**不产生任何订单记录**（下单前订单数不变）
- [ ] 非下单家属查询他人订单 → `3004`；非本家属的老人 → `2006`

### 6.2 合规验收项（不可协商）

- [ ] 任何医疗类提问**不可能**得到含剂量 / 诊断结论 / 疗效判断的回答
- [ ] 输入侧命中医疗意图时**不经 LLM**，直接返回固定拒答模板
- [ ] 输出侧命中禁用词时**整段替换**，原句不残留
- [ ] 推荐叙述**必含**可解释理由；`notes` 的降级说明被**原样**转述
- [ ] 输出中不出现「已指派」「已分配」「自动派单」
- [ ] 响应与助手上下文中**无手机号、无身份证号**
- [ ] 对话历史只存浏览器 `sessionStorage`，**后端不落库**、无新增表
- [ ] 模型服务侧**不持有**用户令牌

### 6.3 门禁项与命令

| 门禁 | 命令 | 判据 |
|---|---|---|
| 后端 | `mvn -B verify` | 全绿（含新增 Java 单测） |
| 前端检查 | `pnpm run lint:check` | **0 警告**（`--max-warnings 0`） |
| 前端单测 | `pnpm run test` | 全绿（含助手相关 vitest） |
| 前端构建 | `pnpm run build` | 生产构建成功 |
| AI 服务单测 | `pytest ai-service/tests -q` | 全绿；**核心断言不依赖 LLM 与网络** |
| 密钥体检 | `python tools/check_secrets.py` | 全绿（含 LLM API Key 规则） |
| 指标字典一致性 | `python tools/check_metric_dict_parity.py` | 全绿 |
| 降级可用性 | 不配置模型端到端跑一次问答 | 返回标准答案且 `degraded=true` |

> 本版为开工态，上表是**判据**，不是实测结果；收口时回填实测数字（体例同 `PRD-V3.4` §6.3）。

### 6.4 错误码（10xxx 智能助手，M14）

| 码 | 含义 | 触发条件 |
|---|---|---|
| `10001` | 提问过于频繁，请稍后再试 | 同一用户单位时间内提问次数超过配置上限 |
| `10002` | 智能助手暂时不可用，请稍后再试 | 计算服务不可用**且**本地 FAQ 兜底也失败 |
| `10003` | 问题内容包含违规表述，请重新描述 | 输入命中辱骂 / 违规引流 |

> 通用 `400` / `401` / `403` / `3004` / `2006` 复用既有语义（`3004` = 不是本单下单家属；`2006` = 无权操作该老人档案）。
> **不占用 9xxx**（语义已固定为统计导出）；1xxx–9xxx 已用满，故新开 **10xxx** 段（AGENTS.md §2.7 段位纪律）。

## 七、已知限制与风险

### 7.1 已知限制（如实披露，不静默）

| 项 | 说明 |
|---|---|
| 距离维度目前恒为 0 | 陪诊员坐标尚未填写，距离维度对所有候选人恒为 0，候选结果里会出现「未填写坐标，距离维度记 0」。这是**如实反映「现在没有距离数据」**，不是缺陷；助手**必须原样转述** |
| 助手看不到实时数据 | 助手的工具数据是本次请求装好的**快照**，不查库、不回调后端做工具调用 |
| 家属端没有陪诊员列表 | 「看看有哪些陪诊员」这类问题只能如实回答「推荐需在下单后给出」 |
| FAQ 时效性靠人工维护 | FAQ 条目与锚点靠人工更新 + 校验脚本保证，不靠模型 |
| 限流阈值是拍板值 | 每用户每分钟 10 次没有真实流量数据支撑 |
| 模型名无默认值 | 未配置模型名时即使配了服务地址也走降级（不报错，避免配置半套时静默空转） |

### 7.2 风险与代价

| # | 风险 | 后果 | 缓解 |
|---|---|---|---|
| 1 | 陪诊员坐标全空 → 距离维度恒为 0，模型可能把「距离**没法算**」美化为「距离**近**」 | 直接误导一个正在决定给哪位老人找陪诊员的人，且属于把「没法算」说成「不匹配」的同款错误 | 三层护栏（§4.3）+ 单测断言：`distanceScore=0` 且 `notes` 含「未填写坐标」时，输出**不含**「距离近」「离得近」「就在附近」 |
| 2 | FAQ 时效性靠人工维护 | 平台规则改了而 FAQ 没改，家属拿到过期答案 | FAQ 条目带 `source` + `anchor`，由校验脚本核对锚点仍存在；规则变更时**必须**同批更新 FAQ |
| 3 | 限流阈值（每用户每分钟 10 次）是拍板值 | 无真实流量数据，可能过松或过紧 | 阈值配置化 + 启动期校验；上线后按实际提问分布调整 |
| 4 | 引入**第二个技术栈**（Python 3.12 + FastAPI + LangChain）与**第二条构建链路**（pytest + venv） | 这是本项目最重的一次技术栈扩张；后来者可能把本版实现当成违规实现 | 依赖清单已逐项获批；**必须同步更新 `AGENTS.md` §0 技术栈表**，把授权写进项目宪法 |
| 5 | FAQ 覆盖面未经真实用户验证 | 当前条目按仓库文档推导，家属真实提问分布未知；命中率低会显得「助手没用」 | FAQ 检索为确定性规则，增删条目零代码改动；上线后按未命中问题回流补条目 |
| 6 | 合规词表外置为共享资源后，任一侧读空即护栏静默失效 | 最危险的一类故障：不报错，医疗回答全部放行，且看起来一切正常 | 两侧**启动期 fail-fast**（读不到 / 词数过少 / 缺少关键词 → 启动失败） |
| 7 | 合规词表条数在文档与代码之间存在出入 | 单测若按文档条数断言，会与真实词表不符 | 以 `ComplianceCheckUtil` 现有列表为准，开工前核对一次并统一口径（条数只作断言用，不影响护栏行为） |
