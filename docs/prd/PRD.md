# 第一篇 · 产品视角(40%)

## 1. 愿景与定位

**一句话定位**:让不会用手机的老人,也能有人陪着把病看好。

**3-5 年愿景**:不做诊断、不碰支付、不接 IM,做老年人就医场景下的「协同操作系统」——把家属、陪诊员、医院、社区医生用一套轻量的状态机 + 数据契约接起来,让 60+ 群体的就医路径不再依赖某一个"会弄手机的家属"。

**核心价值主张**(对 4 角色各给一句话):

| 角色 | 一句话价值 |
|---|---|
| 老人 | 不用学新东西也能把病看好 |
| 家属 | 出差也能看到父母今天挂了什么号、医生说了什么、药有没有吃 |
| 陪诊员 | 接单稳定、凭证齐全、评价公正、纠纷可申诉 |
| 平台/社区 | 数据可看、纠纷可调、过程可追溯 |

**为什么这件事值得做**:中国 60+ 人口 2.6 亿,独居/空巢比例持续上升;子女异地比例上升;社区医院与三甲医院资源不均;现有的"陪诊"行业无凭证、无保险、无评价。银龄伴诊不是抢现有陪诊员的饭碗,而是把灰色市场数字化。

## 2. 产品原则 / 横切约束(产品宪法)

这一章节是**本产品的"宪法"**,后续所有功能描述遇到边界时,均回到这里判定,不重复声明。

### 2.1 适老化原则(老人端体验底线)

| 项 | 数值 / 实现 |
|---|---|
| 基线字号 | ≥ 18px(`--nl-font-base`) |
| 可点击元素最小高度 | ≥ 48px(`$elderly-touch-min`) |
| 文字对比度 | ≥ 4.5:1(WCAG 2.1 AA) |
| 老人模式触发 | `<html class="elderly-mode">` 一键切换 |
| 老人模式菜单 | `meta.elderlyHidden: true` 的路由在老人模式下隐藏 |
| 核心流程点击次数 | ≤ 3 次 |

### 2.2 合规红线(3 条硬约束)

1. **不开诊断、不开药方**——药品字典仅返回通用信息(名称 / 规格 / 通用说明),**禁止**出现"建议服用""推荐剂量""诊断为""可能是 XX 病"等表述。所有药品详情页必须有免责声明。
2. **隐私最小化**——密码 BCrypt 加密(数据库值以 `$2a$` 开头);手机号展示脱敏为 `138****8888`;身份证号展示脱敏为 `110101********4567`;**localStorage 禁止写入密码 / 身份证号 / 完整手机号**;日志禁止打印身份证号。
3. **一期不做**——在线支付(改"线上记账 + 线下结算")、地图导航(改"文字地址 + 签到坐标")、IM 聊天(改"站内信")。

### 2.3 老人账号默认只读

老人账号(ELDER)的所有**写操作**一律由家属代操作。**服务端强校验**(不是只靠前端隐藏按钮),老人 token 调任何写接口直接 403。

## 4. 用户旅程

### 4.1 单人旅程(每角色 1 条)

**老人 · 一日就医陪诊**(典型主旅程,占 80% 场景):

1. 早上 8:00,陪诊员上门接老人
2. 8:30 上车,系统实时显示车辆预计到达时间(简化版:文字描述)
4. 9:00 到医院,科室就诊
5. 11:00 取药离院
6. 下午到家,家属视频确认
7. 晚上 19:00,服药提醒推送 → 老人按"已服"(家属代操作)

**家属 · 远程下单**:

1. 周一上午 9:00,出差路上收到"母亲需要复诊"提醒(站内信 + 推送)
2. 打开 APP,选老人 → 选医院 / 科室 → 选时间 → 文字地址
3. 提交订单 → 进入待接单大厅
4. 陪诊员接单 → 收到站内信 + 推送
5. 就诊日实时看陪诊员打卡 → 完成后评价

**陪诊员 · 接单 - 执行 - 结算**:

1. 早 8:00 看订单大厅 → 抢单 → 自动校验资质
2. 接单后按 出发 → 到院 → 就诊 → 取药 → 离院 → 完成 6 节点打卡
3. 完成订单 → 跳结算页(线上记账) → 收到评价
4. 周五看本周接单数 / 评分 / 收入排行

**管理员 · 早会巡查**:

1. 早 9:00 看数据看板(订单趋势 / 漏服率 / 投诉率)
2. 处理昨日新提交的陪诊员资质审核(通过 / 驳回 + 原因)
3. 看投诉列表 → 调纠纷 → 强制改终态 + 通知双方
4. 周五导出本周运营数据 Excel

### 4.2 跨角色协同旅程

**核心闭环 1 · 陪诊全流程**(家属 ↔ 陪诊员):

```
家属下单 → 陪诊员接单 → 6 节点打卡 → 家属实时看进度 → 完成后评价
   ↓          ↓              ↓                  ↓                ↓
订单 PENDING → ACCEPTED → IN_SERVICE → COMPLETED → REVIEWED
```

任何一环断开 → 双方都能在订单详情看到完整时间线 → 纠纷时管理员强制改终态

**核心闭环 2 · 用药闭环**(家属 / 陪诊员 ↔ 系统):

```
家属创建用药计划 → 每日 07:00 系统生成当日任务 → 老人服药 → 陪诊员/家属确认
                                                          ↓(超时未确认)
                                                    系统判定漏服 → 推送家属
```

跨日 / 跨餐自动合并显示;药品字典永远只给"通用信息 + 免责声明",**不出现剂量建议**

## 6. 功能模块详述

> 每个模块仅给出**产品视角的目标与关键能力**;工程实施见 `plan.md §三` 对应小节;接口契约见 `docs/api/0X-xxx.md`;关键模块的设计评审见 `docs/agents/designs/Mx-xxx.md`。

### M0 工程骨架 → `plan.md §M0`

建立前后端工程骨架,前后端两条命令可启动;接口未实现时返回结构化错误(非白页 / 非 500 堆栈);统一响应体 `Result<T>` + 全局异常处理 + Logback 分级;Knife4j `/doc.html` 可访问;ESLint + Prettier + Alibaba Java 规范插件提交前拦截。

### M1 数据库 → `plan.md §M1` · `docs/db/`

20 张业务表 + 30-200 条种子数据 / 表,覆盖空字段 / 超长文本 / 非常用药 / 跨天用药边界;Flyway 增量迁移(`V1/V2/V3` 已就绪);关键查询(订单按状态 + 时间、用药任务按用户 + 日期、陪诊员按资质筛选)走索引,EXPLAIN 无 ALL。

### M2 认证鉴权 → `plan.md §M2` · `docs/api/01-auth-user.md`

JWT accessToken 120 分钟 / refreshToken 7 天 + Redis 黑名单;BCrypt 密码;图形验证码 5 分钟过期 + 登录失败次数限制;**老人账号写操作 100% 服务端强校验**;手机号 / 身份证号接口脱敏 + 日志脱敏。**4 角色 × 3 类接口 = 12 条越权用例必须通过**。

### M3 用户档案 → `plan.md §M3` · `docs/api/02-elder-family.md`

老人档案身份证号加密存储 + 接口脱敏;家属通过邀请码 / 手机号验证绑定老人(1 家属可绑多老人);陪诊员入驻提交认证资料 + 资质证件上传 + 接单偏好(区域 / 时段);管理员审核陪诊员资质(通过 / 驳回 + 原因);用户封禁 / 解封。**未审核陪诊员看不到订单大厅、不能接单**(前后端双重拦截)。

### M4 陪诊订单 → `plan.md §M4` · `docs/api/03-order.md` · `docs/agents/designs/M4-order.md`

订单状态机 **5 状态 + 1 终态**:`PENDING → ACCEPTED → IN_SERVICE → COMPLETED → REVIEWED`;取消路径分两条——**家属**仅 `PENDING → CANCELLED`,**管理员强制** `PENDING/ACCEPTED/IN_SERVICE/COMPLETED → CANCELLED`(`REVIEWED` 为终态,无出边)。**禁止跳级、禁止回退**,仅 ADMIN 可强制改终态(走 M9 纠纷处理)。接单走 `@Version` 乐观锁,**JMeter 50 并发抢同一单 → 数据库只有 1 条成功接单记录**,`version` 仅 +1。每次状态变更写 `order_status_log` 时间线。完成时生成费用明细(代垫 / 服务费),**不做在线支付**。

### M5 陪诊执行 → `plan.md §M5` · `docs/api/04-companion-execution.md` · `docs/agents/designs/M5-execution.md`

陪诊员 6 节点打卡:**出发 / 到院 / 就诊中 / 取药 / 离院 / 完成**,节点顺序不可逆(可跳过,不可回退);同一订单同一节点只能打一次。打卡落 `order_checkin` 同时写 `companion_track` 轨迹点。**打卡坐标偏离订单地址 > 2000 米视为无效打卡**(详见 §8.3)。WebSocket 推送家属端,3 秒内可达。**断线 30 秒自动重连,重连后补齐未读事件**(详见 ADR-0001)。

### M6 用药管理 → `plan.md §M6` · `docs/api/05-medication.md` · `docs/agents/designs/M6-medication.md`

药品字典**仅通用信息 + 免责声明**——名称 / 规格 / 通用适应症说明 / 注意事项;**禁止任何剂量 / 服用建议**。用药计划 CRUD:药品、剂量(由家属录入,非系统建议)、频次、起止日期、饭前 / 饭后。每日 07:00 定时任务生成当日 `medication_task`,**Redis 分布式锁**保证多实例只执行一次(详见 ADR-0002)。每 30 分钟扫描漏服并推送家属。**全站 grep "建议服用""推荐剂量" 必须为空**。

### M7 评价投诉 → `plan.md §M7` · `docs/api/06-review-complaint.md` · `docs/agents/designs/M7-review.md`

订单完成才出现评价入口(其他状态调评价接口直接拒);1-5 星评分 + 标签(准时 / 耐心 / 专业…) + 文字 + 匿名开关;同一订单评价唯一;陪诊员评分 = 所有有效评价 `AVG`。投诉 3 状态(待处理 → 处理中 → 已结案)全程留痕;敏感词过滤拒绝提交。

### M8 站内信 → `plan.md §M8` · `docs/api/07-message.md` · `docs/agents/designs/M8-message.md`

4 类模板:**订单事件 / 资质审核结果 / 漏服提醒 / 系统公告**。WebSocket 推送未读数变化,顶栏红点提示;已读状态多端一致。

### M9 管理后台 → `plan.md §M9` · `docs/api/08-admin.md` · `docs/agents/designs/M9-admin.md`

陪诊员资质审核 + 用户封禁 / 解封 / 重置密码 + 订单纠纷仲裁(**强制改终态 + 双方通知**)。所有管理动作写 `admin_oper_log`(操作人 / 目标 / 动作 / 时间)。管理端与业务端隔离(ADMIN 角色专属路由 + 接口)。

### M10 统计导出 → `plan.md §M10` · `docs/api/09-statistics-export.md` · `docs/agents/designs/M10-statistics.md`

订单量 / 订单完成率 / 用户增长(日 / 周 / 月维度) / 陪诊员接单排行 / 漏服率 5 类图表。**统计接口在 1 万条订单下响应 < 2s**(缓存 + 索引双优化,详见 ADR-0003)。EasyExcel 导出按当前筛选条件,列头中文、数据与页面一致。

### M11 适老化 → `plan.md §M11`

顶栏开关一键切换老人模式(无需刷新);全局字号 / 对比度 / 触控区同时变化;老人端隐藏次要菜单(`meta.elderlyHidden: true`);**核心流程 ≤ 3 步**(详见 §2.1)。本模块横切整个前端,所有页面必须满足适老化基线。

### M12 测试质量 → `plan.md §M12`

JUnit5 + Mockito Service 单测覆盖率 ≥ 60%(JaCoCo 报告为证);**4 角色 × 3 类接口 = 12 条越权用例 100% 通过**;JMeter 50 并发抢单报告归档;3 份迭代测试报告(迭代二 / 三 / 五)。

# 第三篇 · 工程视角(25%)

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标值 | 验证手段 |
|---|---|---|
| 抢单接口并发 | 50 并发 → 1 成功 / 49 失败 | JMeter 压测报告 |
| 统计接口响应 | 1 万条订单 < 2s | JMeter + EXPLAIN |
| 实时推送延迟 | 3 秒内到家端 | 端到端手动测试 |
| 单测覆盖率 | Service 层 ≥ 60% | JaCoCo 报告 |
| 关键查询 | EXPLAIN `type` 不为 ALL | `docs/db/03-索引设计与EXPLAIN.md` |

### 7.2 安全

| 维度 | 要求 |
|---|---|
| 密码存储 | BCrypt(值以 `$2a$` 开头) |
| 越权拦截 | 服务端强校验(前端隐藏仅提升体验,不构成安全边界) |
| 老人账号写操作 | 一律 403(由家属代操作,详见 §2.3) |
| 敏感数据 | 接口脱敏 + 日志脱敏 + localStorage 禁写密码 / 身份证号 / 完整手机号 |
| XSS / CSRF | 后续可在网关层加;本期由前端框架默认防御 |

### 7.3 可观测性

| 维度 | 实现 |
|---|---|
| 日志分级 | `nianglin.log` / `nianglin-error.log`,保留 30-60 天 |
| 操作审计 | `admin_oper_log` 表,所有管理动作留痕 |
| 业务异常 | 全局异常处理统一转 `Result.fail(code, message)` |
| 业务追踪 | `order_status_log` 订单全生命周期时间线 |

### 7.4 可扩展性

| 项 | 预留 |
|---|---|
| 文件存储 | 一期本地 `./uploads/{yyyyMM}/{uuid}.{ext}`,后续可替换为对象存储(M13 现阶段被排除) |
| 实时通信 | WebSocket(详见 ADR-0001),可后续替换 SSE 或消息队列 |
| 模块解耦 | 按模块子包(`controller/{auth,user,order,...}`),允许后续拆微服务 |
| 国际化 | 字符集统一 utf8mb4 / UTF-8;文案集中在 `frontend/src/i18n/`(留位,本期不实装多语言) |

## 8. 业务规则

### 8.1 状态机

| 状态机 | 状态序列 | 关键约束 |
|---|---|---|
| 订单 | `PENDING → ACCEPTED → IN_SERVICE → COMPLETED → REVIEWED`；家属仅 `PENDING → CANCELLED`；管理员强制 `PENDING/ACCEPTED/IN_SERVICE/COMPLETED → CANCELLED`（`REVIEWED` 终态无出边） | 禁止跳级、禁止回退;仅 ADMIN 可强制改终态(走 M9) |
| 用药任务 | `待服 → 已服 / 漏服` | 每 30 分钟扫描;超时未确认自动判定漏服 |
| 陪诊员资质 | `待审 → 通过 / 驳回` | 驳回必须填原因;通过前不能接单 |
| 投诉 | `待处理 → 处理中 → 已结案` | 每步记录操作人与时间 |
| 用户状态 | `正常 → 封禁` | 封禁后已签发 token 立即失效 |

### 8.2 权限矩阵(4 角色 × 关键接口)

| 接口类型 | ELDER | FAMILY | COMPANION | ADMIN |
|---|---|---|---|---|
| 查看自己订单 | ✅ | ✅ | ✅ | ✅ |
| 创建订单 | ❌(403) | ✅ | ❌ | ❌ |
| 接单 | ❌ | ❌ | ✅(需审核通过) | ❌ |
| 开始服务 / 完成订单 | ❌ | ❌ | ✅(限本人订单) | ❌ |
| 评价订单 | ❌ | ✅(限本人订单) | ❌ | ❌ |
| 投诉 | ✅(限自己订单) | ✅(限自己订单) | ✅(限自己订单) | ✅(任何订单) |
| 审核陪诊员资质 | ❌ | ❌ | ❌ | ✅ |
| 强制改终态 / 纠纷仲裁 | ❌ | ❌ | ❌ | ✅ |
| 用户封禁 / 解封 | ❌ | ❌ | ❌ | ✅ |
| 查看统计看板 / 导出 Excel | ❌ | ❌ | ❌ | ✅ |
| 资质审核 | ❌ | ❌ | ❌ | ✅ |

> Service 层做归属校验(家属 A 不能读家属 B 的订单),前端隐藏仅提升体验,**不构成安全边界**。

### 10.2 风险清单

| 风险 | 类别 | 影响 | 缓解措施 |
|---|---|---|---|
| 老人不会用 → 实际无人用 | 用户接受度 | 课程演示效果差 | 老人模式 + 家属代操作兜底 |

| M13 部署上线阶段被排除 | 范围 | 演示只能本机跑 | 见 ADR-0004 兜底(本机 `mvn spring-boot:run` + Knife4j `/doc.html`) |

| 合规红线被无意突破 | 合规 | 全站 grep 守卫 + 静态检查 | §9.1 合规 grep + Plan §M6 验收 |
