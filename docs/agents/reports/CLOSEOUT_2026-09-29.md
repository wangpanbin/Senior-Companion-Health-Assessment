## 5. 本轮修复清单

### 5.1 🔴 D2 · `SecurityConfig` CORS 兜底值（真实代码缺陷）

**根因**：CORS 端口漂移修复（BASELINE §3.2）当时只改了 `WebMvcConfig.java:30`，
**漏了 `SecurityConfig.java:82`**。两处读同一个 `nianglin.cors.allowed-origins`，
但各有各的 `@Value` 兜底串。

**为什么开发期看不出来**：

| profile | `nianglin.cors` 配置 | 走兜底？ |
|---|---|---|
| `dev` | ✅ 有（`http://localhost:[*],…`） | 否 → 缺陷被掩盖 |
| `prod` | ❌ **完全没有 `nianglin.cors` 段** | **是 → 生产会真的放行 5173** |

结果会是：同一进程内 **Spring Security 层放行 5173、MVC 层放行 5141**，行为不一致。

**修复**：`SecurityConfig.java:82` 兜底值 `5173` → `5141`，与 `WebMvcConfig.java:30` 对齐。

**回归**：`mvn test` → **592 tests / 0 failures / 0 errors / 0 skipped**，无回归。

**规范同步**：`AGENTS.md` §2.10 CORS 段落补一条约束 ——
「两处 `@Value` 兜底默认值必须同步，改端口时一起改，并确认目标 profile 是否真的会走到兜底」。

## 8. 给下一位接手者的话

1. **看到中文乱码，先怀疑 PowerShell 控制台代码页**（§1.1 与 §5.5 是同一个坑的两面）——
   不要据此去改文件编码。
2. **跑 `.ps1` 前先看有没有 UTF-8 BOM**。无 BOM 的脚本用 Windows PowerShell 5.1 跑会
   `ParserError`；用 `pwsh` 跑。`tools/e2e/` 下 3 个脚本都是无 BOM。
3. **build 必须排在 lint 之后** —— ESLint 对 `<style lang="scss">` 内的 `$变量` 零感知。
4. **测试日志里的 `ERROR` 不等于失败**，看 `Tests run` 汇总行。
5. **E2E 已全自动夹具**：跑前 `globalSetup` 自动 snapshot，跑后 `globalTeardown` 自动
   `restore` + `verify`。**不要再手动 UPDATE 恢复数据**（BASELINE 那种做法已过时），
   但**看到 `[verify] 全部回到基线` 才算跑干净**。
6. **改了 `application-dev.yml` 里的配置不代表生产也变了** —— `prod` profile 常常缺该配置段，
   这正是 `SecurityConfig` 兜底缺陷能活到今天的原因（§5.1）。
